## 2. 缺口详情与方案

### 2.1 P0 书签归档后的顺序（缺陷）

**现状**

- 书签列表换位用的是**全局** `bookmarks` 的下标（`BookmarksPage.vue:322-324`），与
  `service.ts` 在全局 `data.bookmarks` 上的 splice 一致，**没有错位问题**（本规划初稿曾
  误判为局部下标，核实后修正）。
- `BookmarksPage.vue:236` `moveTo` 改文件夹只改 `folderId`，不动 `order`
  （`service.ts:1017-1026`）：拖进文件夹后按旧全局序号落位，而不是追加到目标文件夹末尾。

**方案**

`saveBookmark` 检测 `folderId` 变化时，把 `order` 追加到全局末尾（`max(order)+1`，排除
自身），与新建书签的口径一致（`service.ts:1030`）。

**测试**：`tests/bookmarks.test.ts` 增加「归档到文件夹追加」「移出文件夹追加」两个用例。

---

### 2.2 P1 标签排序

**现状**：`data.tags` 数组顺序即展示顺序（`types.ts:586`）；`saveTag` 新标签 `push` 到末尾（`service.ts:455`）；无重排入口。

**方案**

- Service：`moveTag(id, toIndex)`，照 `moveView`（`service.ts:919`）的数组 splice + 越界 clamp，不引入 `order` 字段。
- IPC：`tagMove: "site-tag:move"`（沿用现有 `tagSave: "site-tag:save"` 前缀）+ `EnsembleApi.moveTag`。
- 链路：`preload/index.ts` → `main/index.ts` handle（`workspace.moveTag` + `broadcastWorkspace` + snapshot）→ `stores/workspace.ts` `moveTag`。
- UI：`TagsPage` 行可拖拽。行内有内联编辑输入框，**必须用 `GripVertical` 手柄**起拖，避免抢焦点/拖选文本；落点显示插入线。
- 无数据迁移；「未打标签」分组固定最后，不参与排序。

**测试**：新增 `tests/tag-order.test.ts`（首/尾/越界/不存在 id/重编号幂等）。

---

### 2.3 P1 书签文件夹同级排序

**现状**：`BookmarkFolder.order` 已存在（`types.ts:99`），快照按 order 排序（`service.ts:306`），新建追加到同级末尾（`service.ts:1076-1088`）；UI 只有「拖入文件夹」（`BookmarksPage.vue:289-300`），没有同级换位。

**方案**

- Service：`moveBookmarkFolder(id, toIndex)`，只在**同一 `parentId` 的兄弟集合**内重排并重编号；不改 `parentId`（改父级仍走 `saveBookmarkFolder`）。
- IPC：`bookmarkFolderMove: "bookmark-folder:move"` + preload + store。
- 手势分区（关键设计）：文件夹行按指针纵向位置分三段——
  - 上 25%：插入到该文件夹之前（显示上边线）
  - 下 25%：插入到之后（显示下边线）
  - 中间 50%：拖入该文件夹（保持现有语义）
- 拖书签行时整行仍是「拖入」，不分区，避免两种手势混淆。
- 边界：不能把文件夹排到自己的子树里（现有 `canDropInto` 的祖先检查沿用）。

**测试**：`tests/bookmarks.test.ts` 增加「同级重排」「跨父级不重排（只走 saveBookmarkFolder）」「边界」。

---

### 2.4 P2 站点排序

**现状**：`data.sites` 数组顺序即展示顺序；`SitesPage` 按标签分组（一个站点可出现在多个组）；账号页、流程页分组顺序也吃这个顺序。

**方案**

- Service：`moveSite(id, toIndex)`（数组 splice）。
- IPC：`siteMove: "site:move"` + preload + store。
- UI：`SitesPage` 组内拖拽；落点 = 目标站点在**全局数组**中的下标（照 `ViewsPage.vue:203-234` 的可见索引→存储索引换算）。
- 约束：不做跨组拖拽（语义=改标签）；多标签站点在任一组内拖动都会改全局顺序，其它组随之变化——交互提示里写清「顺序全局生效」。
- 键盘替代：暂无，与现有视图/书签拖拽保持一致（后续统一补）。

**测试**：新增 `tests/site-order.test.ts`。

---

### 2.5 P2 流程步骤拖拽

**现状**：编辑器内 `moveStep` 上下箭头（`FlowsPage.vue:191-197`）；`draft.steps` 顺序即执行顺序，提交时整体保存。

**方案**

- 纯前端：`draft.steps` 数组重排，**无 IPC / 无 service 改动**。
- 每个 step 行加 `GripVertical` 手柄起拖（行内有多个输入框，不能整行 draggable）。
- 保留上下箭头：键盘可达路径不退化。
- 落点显示插入线，拖拽结束后按新顺序渲染编号（`index + 1`）。

**测试**：`tests/flows.test.ts` 或 `flow-service.test.ts` 断言保存后的步骤顺序（若已有覆盖则补一条重排后的保存用例）。

---

### 2.6 P3 暂不做（记录原因）

| 对象 | 原因 |
| --- | --- |
| 账号顺序 `IdentitiesPage` | 分组后每组数量少；跨组拖拽=改归属，风险高；先观察真实需求 |
| 流程列表顺序 | 已按站点分组，组内数量少，排序收益低 |
| 布局预设 | 只在两个下拉里出现，没有管理列表 |
| 自定义搜索引擎 | 同上，且新建即选中 |
| 视图成员（ViewsPage 侧） | 弹窗内已支持换位；主界面只承担槽位指派 |

## 3. 统一实现约定

1. **数组顺序优先**：视图/标签/站点/账号/流程用数组顺序即展示顺序；只有书签与书签文件夹用 `order` 字段（同级分组需要独立序号）。新增对象不要随意加 `order`。
2. **落点语义**：drop 在目标行上 = 移动后占据目标行位置（与 `moveView` 现有语义一致，service 内部「先 splice 出、再按目标下标插入」）。
3. **筛选/分组必须换算**：可见列表下标 ≠ 存储下标时，先换算再调 IPC（范式见 `ViewsPage.vue:203-234`）。
4. **IPC 纯数据**：拖拽状态用 `shallowRef`，跨 IPC 的落点对象必须重新拼纯字面量（踩坑库 2026-10-22「拖拽标签页看起来在拖，松手什么也没发生」）。
5. **拖拽手柄**：行内可编辑/可点击的行（标签行、流程步骤、文件夹行）一律用手柄起拖，避免与输入、点击、文本选择冲突。
6. **视觉统一**：沿用现有 `.dragging` / `.drop` 样式词；插入位置用 2px 边线，不用整行变色。
7. **可访问性**：新增可拖拽列表至少保留一条非拖拽路径（箭头/菜单），aria-label 走 i18n（`messages.ts` 中英双语）。
8. **不引入拖拽库**：现有原生 HTML5 DnD 已覆盖 5 处，继续手写；不新增依赖（AGENTS.md「新增依赖先确认是否真需要」）。
9. **可复用性**：目前 3 处拖拽实现各自独立（ViewsPage / BookmarksPage / BookmarkGrid）。本次只新增 3 个列表，先不抽公共 composable；若第 4 个出现再抽 `useListDrag`，避免过早抽象。
