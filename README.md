# Ensemble · 同台

**一套系统里的多个账号，一屏同时在线。**
测多角色权限，别再反复退出登录了。

一个本地多账号浏览器工作台：同一套系统里让多个身份同时在场，并行操作、并排对比，
验证每个身份看到的内容和能做的操作是否符合预期。

## 为什么

**同一个页面，管理员看得到删除按钮，成员看不到——你怎么确认？**

换个账号登录看一眼，答案就有了。但真正要确认的从来不止一个按钮：租户 A 的数据不该出现在
租户 B 的搜索里，灰度功能只对名单内的人开放，免费版和付费版卡在不同的边界上。这些差异只能在
同一套系统的多个账号之间来回对照，而每换一次身份都要退出登录、清 Cookie、重新输密码——
浏览器多开又常常互相串登录态。

Ensemble 把这些窗口变成一张可以编排的台面：每个账号一个完全独立的浏览器 Profile，一键拉起一组，
关掉就回收。

它有两个浏览器表面：

- **内置浏览器（主界面）**：页面跑在应用自己的窗口里，不弹系统窗口。一块屏幕可以同时显示几个
  账号（1×1 到 3×1，或自定义布局），AI 通过 MCP 直接在里面读写页面、点击输入、截图，
  人随时能看见并接手。这是日常操作和自动化用的表面。
- **外部真实浏览器**：需要确认「在真人环境里也一样」时，用你系统里的 Chrome、Edge、Brave 或 Firefox
  启动同一组账号。Cookie、扩展、下载、原生密码管理器行为与真实用户完全一致。

两种表面共用同一套站点、账号、凭据与视图模型；切换意味着重新登录一次——内置与外部各自维护独立的登录态。

## 典型场景

权限只是最容易上手的那个例子。凡是「同一套系统、多个身份、需要确认差异」的场合都用得上：

| 场景 | 要回答的问题 |
| --- | --- |
| **角色与权限** | 删除按钮是不是只有管理员能看到？普通成员是不是真的被挡住了？ |
| **多租户与数据隔离** | 租户 A 的账号会不会看到租户 B 的数据？搜索、导出、详情页都查一遍 |
| **功能开关与灰度** | 同一个功能，对灰度名单里的账号是否按预期放开，对名单外是否真的关闭 |
| **套餐与等级差异** | 免费版和付费版的功能边界是否与定价页一致，升级后是否立即生效 |
| **跨账号协作** | A 提交后 B 是否收到待办、审批后 C 看到的状态是否同步正确 |

这些场景的共同点是：**必须同时在场才能验证**。串行地退出再登录，既慢，也容易漏掉「切换之后才出现」的问题。

## 核心概念

| 概念 | 含义 | 是否隔离 |
| --- | --- | --- |
| **站点** | 登录配方与归属：站点地址、登录入口、登录检测地址、默认凭据；可用标签归类 | 否，不限定作用域 |
| **身份** | 一个登录账号 + 一个独立的浏览器 profile；可引用其他站点的身份 | 是，完全隔离 |
| **视图** | 一块共享屏幕区域：同时显示哪几个账号、用哪个布局；可以跨站点 | 否，是编排 |

站点 1—N 身份，站点 1—N 视图。不建视图也能当普通浏览器用；视图从运行栏手动创建，
再把标签拖进去。站点之间仍然完全隔离——每个身份一个 profile，切站点不共享登录态——
但站点不再是一个全局筛选项：账号页按站点分组列出全部账号，视图可以跨站点。
标签是唯一一套，站点、账号、视图都能挂，筛选时账号也会继承所属站点的标签。

## 能力

- **内置浏览器**：页面跑在应用自己的窗口里，不弹系统窗口；一块屏幕同时显示几个身份，
  AI 可以直接读写页面、点击输入、截图，人随时能看见并接手
- **视图 = 一块共享屏幕区域**：用运行栏的「创建视图」按钮建一块区域，再把标签拖进去
  （落点决定左右还是上下），切换布局、拖分隔缝改比例；同一时刻只有一个视图在台上，
  其余继续在窗口外运行
- **一个格位 = 一个浏览器实例**：页面里点开的新标签页属于同一个实例（换一页显示），
  不会多占格位；切换它们不用跑去右侧栏——格位头中间的标签条就列着这个实例的页面，
  点一下就换那一格显示哪一页。运行栏一行一个实例，实例自带的页面缩进列在下面
- **默认标签组和视图一样有标签条**：不建视图时舞台顶部同样是一条页面标签条（标签、图标、
  关闭、右键菜单、「＋」齐全）。想并排看时，在运行栏「标签页」组头选一个布局，就把当前
  所有扁平实例收成一个视图铺开
- **台上 / 台下 / 选中**：视图里有几个实例就只显示几个，其余仍在运行；点一下台下实例就换进选中格位，
  再点一次换回来；也可以直接把运行栏的行拖到某个格位上替换。格位号把「现在到底哪几个在屏幕上」
  变成可读的事实
- **一处切换内置 / 外置**：标题栏右上角选一次启动目标，账号页、批量启动、重新登录、视图页的
  启动都跟着它走；同一个菜单里还有「打开干净会话」，选内置就在内置里开、选外部就在外部开。
  运行栏的「添加标签页」永远新建内置标签，悬浮条永远只列外置窗口
- **站点是登录配方，书签是地址**：地址栏旁的新建标签分叉、运行栏的 ＋、以及地址栏输入
  站点名，都能直接打开某个站点——日常打开（用日常档案里已有的登录）、干净打开，或直接用
  某个账号打开（登录态已经在它的分区里）。没有登录要求、也不想建站点的地址，存成书签
- **日常档案**：不带身份的页面（新标签页、书签、地址栏敲的地址）共用一个持久的个人档案，
  在某个站点登录过一次就长期有效——这是让 AI 在已登录的页面上帮忙做事的前提
- **手动登录也能存下来**：在内置浏览器里自己登录后，像浏览器密码气泡一样提示保存；确认后
  打开预填好的账号表单，密码只经过主进程写入加密库
- **站点只负责「去哪、怎么登录」**：没有全局「当前站点」；账号页按站点分组，视图可以跨
  站点，标签一套通用（站点、账号、视图都能挂）。标签管理是左侧导航的一页，每个标签显示
  被多少站点 / 账号 / 视图用到；筛选条固定一行、横向滚动，标签再多也不挤占卡片
- **右侧运行栏**：内置视图、内置扁平标签与外置实例在同一处；视图是块、标签是行，
  可折叠、可整栏收起，点一下就把对应的页面或窗口提到你面前。折叠后仍保留每个实例一个
  站点图标，分组之间的分隔也还在，点图标就能切过去——宽度让给页面，而不是把「有几个窗口在跑」
  藏起来；展开与收起是同一个位置的同一个控件
- **空白页就是搜索框**：启动即开一个空白页，落地页只有一个输入框，输地址直接打开、
  输词语按所选引擎搜索（默认 Bing，可加自定义引擎）；下面是一排书签，双击改名、右键删除、
  拖拽排序，地址栏的星标一键收藏当前页。空白页有内置配色背景，右下角一键切换，选择跟着
  工作区一起导出导入
- **两种浏览器表面**：内置是主界面，外部真实浏览器是保真校验；两者共用同一套账号、凭据与布局
- **运行实例悬浮条**：桌面上一个始终置顶的小条，列出所有运行中的外部窗口（按站点分组）；
  点一下就把对应的浏览器窗口提到最前，最小化也会恢复，**不重启、不重载页面**；
  并实时高亮当前真正在前台的那个窗口，任务栏或 Alt+Tab 切换也会跟着走。
  用不到时收成一个只显示窗口数量的小方块，不占桌面，拖动后自动贴边
- **批量启动**：账号页点「选择账号」勾几个，一次按默认布局铺开，不必逐个点击、被新窗口反复遮挡；
  同一批勾选还能「创建视图」，把它们存成一个有名有布局、下次能重新打开的视图
- **分组可折叠**：站点（按标签）、账号（按站点）、流程（按站点）的分组都能整组收起，
  页头还有一个「全部折叠 / 全部展开」；折叠状态跟着页面记在本地，重启后还在
- **一键收尾**：悬浮条底部、运行栏和托盘菜单都能一次关闭所有实例；视图详情里的停止只关这个视图
  启动的标签，不误伤手动打开或 AI 新增的页面
- **切换回执**：从悬浮条切到外部窗口后，目标窗口上方短暂浮出账号名（约 2 秒），
  页面全都一样时也能确认切到了谁；浮层不挡鼠标、不抢焦点、不注入被测页面
- **启动即填**：窗口打开后自动填入账号密码，并在页面上还有未配置的输入框时点名提示
- **页面缩放**：内置浏览器里按 Ctrl + 加号/减号缩放当前这一页，Ctrl + 0 回默认；
  设置里有全局默认缩放，手动调过的页面不会被它覆盖。每页各管各的，四宫格里可以一格放大
  看表格、另一格保持原样
- **开发者工具**：默认停靠在页面右侧（这一格里分屏），需要时可以拆成独立窗口；工具栏的
  按钮会跟着开/关状态高亮
- **账号密码之外的表单**：租户名、公司码等字段按标签匹配填充，站点级下发、身份级覆盖
- **身份引用**：一个身份可以引用另一个站点的身份，用户名、密码、显示名、角色完全同步，
  登录态与 profile 各自独立；想各改各的就断开引用
- **地址变更检测**：站点记住上次成功登录的地址，地址变了会拦住密码填充并要求一次确认
- **视图跨站点复制**：把这套编排搬到另一个站点，同名身份直接复用、没有的建引用身份
- **真实浏览器隔离**：每个身份独立 profile，登录态、Cookie、扩展互不影响
- **视图编排**：一键拉起一组账号，边到边平铺，不留无用外边距
- **按角色摆窗口**：把成员拖到槽位即可指定谁在哪个位置，换位后正在运行的窗口会跟着移动
- **布局可自定义**：外置模式内置 `无布局 / 1×1 / 2×1 / 1×2 / 2×2 / 3×1`，内置浏览器用
  `无布局（= 1×1）/ 2×1 / 1×2 / 2×2 / 3×1`，格位之间还能拖分隔缝改比例；也可以拖动方块画自己的
  布局并保存成预设，拖动时自动吸附到屏幕边缘与相邻槽位，并显示对齐参考线
- **无布局模式**：小屏幕或需要全屏对照时，每个窗口都以整屏尺寸打开、互相重叠，用任务栏切换，
  不必把屏幕切成四块看不清的小窗
- **成员可单独重开**：误关某个身份的窗口时，在视图详情里点「重新打开」，不必重启整组
- **会话健康中心**：一屏看清所有账号里谁正常、谁掉线、谁还没开窗口；可一键检测全部、
  一键为所有过期身份打开登录页并填好凭据
- **恢复上次视图**：设置里开启后，冷启动在内置浏览器里按原布局恢复上次的视图
- **凭据保护**：系统密钥环（DPAPI / Keychain / keyring）加密，可再加一层应用主密码
- **干净会话**：外部模式下是关闭即删除的临时窗口（独立 profile 目录）。内置模式下是每次
  打开一个内存级会话——退出即消失，两次干净打开之间也互相看不到。入口在顶栏的浏览器选择
  菜单里，跟随那里的选择决定用内置还是外部浏览器
- **日常档案**：内置模式下不带身份的页面落在同一个持久档案里，登录一次长期有效；
  它与干净会话是两个世界，书签打开时用的是日常档案的登录
- **进程回收**：退出时按 profile 路径精确回收自己启动的浏览器，不碰你日常用的窗口
- **两条入口各司其职**：左侧导航管浏览器 / 站点 / 身份 / 视图 / 标签 / 流程 / 设置；顶栏只剩品牌与
  启动目标（内置 / 外置）
- **AI 直接录入**：内置 MCP 端点，AI 在容器或数据库里建好账号后，直接写入站点、身份与视图；
  也能操作内置浏览器——给它一个测试环境地址和超管账号，它能把租户账号建完、存好、摆上舞台
- **流程是可复用的资产**：AI（或你自己）把一次走通的页面操作存成流程——一串带参数的步骤，
  下次一句话重跑，不必再一步步试。流程由步骤组成而不是脚本，看得懂、改得动、能用界面调整
- **配置导入导出**：整份工作区可导出成 JSON，换机器时连加密密码一起带走
- **账号可以分享**：只想把某个站点（也可以是某个账号）的登录交给别人时，在账号页勾选后导出
  一份账号包；对方导入即用，不用重新注册。和整机迁移的配置导出分开，不带你的视图与布局
- **关闭进托盘**：关窗不退出，浏览器与 AI 端点继续运行；彻底退出会一并停止
- **应用内自动更新**：启动后在后台检查新版本，有更新时弹窗显示简短摘要，点一下即可下载、
  校验并安装，装完自动重启；不用再去 GitHub 下载安装包，也不容易触发浏览器的下载拦截

**页面长得一模一样时，怎么确认切对了人？** 这是多账号场景最实际的麻烦。悬浮条会实时高亮「当前真正在前台」
的那一行——它读的是系统前台窗口，所以你自己用任务栏或 Alt+Tab 切换，高亮也会跟着走。
点下去之后，被切到的窗口上方会短暂浮出一个半透明的账号名，两秒后淡出：

<p align="center">
  <img src="docs/diagrams/overlay-switch.zh.svg" alt="从悬浮条切换窗口，并在目标窗口上显示账号名" width="900" />

## AI 接入

让 AI 帮你在容器里建账号，然后直接把账号录进 Ensemble——省掉手工一条条填表：

1. 设置页打开「AI 接入」，得到回环地址与 Bearer Token（底栏右边的 AI 入口点一下就到这里，那里的小圆点也显示端点是否在运行）；
2. 把配置片段粘进你的 AI 客户端（Claude Code、ZCode 等支持 MCP 的客户端）；
3. AI 调 `create_site` 建站点、`create_identities` 批量录身份、`create_view` 编排视图，
   `open_browser_view` 直接在内置浏览器里打开，或 `launch_view` 走外部窗口。

AI 的权限不止于读写数据——它还能**驱动内置浏览器**。所以一个完整的建号流程可以整段交给它：
给一个测试环境地址、超管账号密码和租户名，让它登录超管、在后台点出几个不同类别的租户，
再把每个租户的管理员连同它自己的租户名存成账号。你最后只看到一台舞台上并排的几格，
每格已经登在对应的租户里。

### 例子：一句话把测试环境的租户账号建齐

```
在内置浏览器里帮我把 http://localhost:3000 这个测试环境配好：
超管 super@example.test / super-secret，租户名「默认租户」。
用超管登录后台，建三个租户：租户 A（标准版）、租户 B（专业版）、租户 C（试用版），
各配一个管理员账号，密码统一 Tenant-1234，然后把这四个账号都存成身份，
最后拉一个 2×2 的视图一起打开。
```

AI 依次做的事：

| 步骤 | 工具 |
| --- | --- |
| 存站点与站点默认密码 | `create_site`（`password`） |
| 存超管账号，连同租户名 | `create_identity`（`extraFields`） |
| 以超管身份打开页面并登录 | `open_browser_tab` → `fill_browser_login` → `click_browser_element`（按按钮文字） |
| 等后台跳转完成 | `wait_browser`（页面内轮询，一次调用等到底） |
| 读懂后台的租户表单 | `read_browser_page`（每个输入框旁边那行标签也一并给出） |
| 填租户名、管理员账号、初始密码 | `fill_browser_form`（一次填完，密码框不进审计日志） |
| 逐个存成身份，带上各自的租户名 | `create_identities`（`extraFields` 逐项） |
| 编排并打开 | `create_view` → `open_browser_view` |

交互类工具都按**人能读的东西**定位：`label: "用户名"`、`text: "创建租户"`，而不是
`:nth-of-type` 拼出来的长路径，后者在组件库页面上多一个条件字段就失效。等异步渲染用
`wait_browser`（`visible` / `hidden` / `text` / `url` / `value`），不要自己 `sleep` 再读——
一次往返就够了，也不会在两次调用之间被页面自己变掉（菜单失焦关闭、选项晚一帧出现）。

过程中页面就在主窗口里，你随时能看见、接手或打断。已经保存过的账号再次登录不会再问
「要保存这个登录吗」——只有凭据库里还没有的密码才会弹提示。

### 例子：一遍跑通的操作，下次一句话重跑

同样是建租户。第一次 AI 要靠 `read_browser_page` 摸索表单、试错定位；走通之后它可以直接
用 `save_flow` 把这条路径存下来：

```jsonc
{
  "siteId": "…", "name": "创建租户",
  "params": [
    { "name": "tenant", "label": "租户名", "required": true },
    { "name": "kind", "label": "套餐", "default": "标准版" }
  ],
  "steps": [
    { "action": "navigate", "url": "/admin" },
    { "action": "wait", "condition": "visible", "text": "创建租户" },
    { "action": "read", "text": "ORD-", "as": "order" },           // 把页面上的订单号收进变量
    { "action": "fill", "label": "租户名称", "value": "{{tenant}}" },
    { "action": "select", "label": "套餐", "option": "{{kind}}" },
    { "action": "fill", "label": "备注", "value": "订单 {{order}}" },  // 再用到前一步读到的值
    { "action": "click", "text": "创建租户" },
    { "action": "wait", "condition": "text", "expect": "{{tenant}}" }
  ]
}
```

之后换租户名、换套餐都是 `run_flow({ id, params: { tenant: "客户 B", kind: "专业版" } })`
一次调用。左侧导航的「流程」页能看到这些资产：按站点分组、逐步展开、直接运行（参数表单
带默认值，密码类参数输入框打码）、也能在界面上改步骤和顺序。

<p align="center">
  <img src="docs/screenshots/flows.png" alt="流程页：按站点分组的可重跑步骤" width="900" />
</p>

同一页的编辑器里可以改参数、加删步骤、调顺序；字段随动作切换，只显示这一步真正用得上的项：

<p align="center">
  <img src="docs/screenshots/flows-edit.png" alt="流程编辑器：参数、步骤与动作" width="900" />
</p>

流程刻意做成**步骤清单而不是脚本**：每一步仍然走和手动操作完全相同的输入路径，所以人到
界面上能看懂、能改、能加一步；参数与变量在保存时就校验（未定义的 `{{变量}}` 会被拒绝，
不会等到运行到一半才炸）；某一步失败就停下并指出是第几步、什么原因，不会写进半套数据。

服务是纯本地 HTTP + JSON-RPC（MCP 2025-06-18 协议子集），只监听 `127.0.0.1`，
校验 `Host`/`Origin` 防 DNS 重绑定，所有请求都要 Bearer Token。默认 47821 端口，可改。

权限分三档，都在设置页开关：

| 权限 | 覆盖的工具 | 默认 |
| --- | --- | --- |
| 读 | 列出站点 / 身份 / 视图 / 布局 / 流程、工作区概览 | 始终开放 |
| 写 | 创建与修改站点、身份、视图、布局、流程；写入密码 | 开 |
| 运行 | 启动 / 停止窗口、检测登录态、驱动内置浏览器、运行流程 | 开 |
| 删除 | 删除站点 / 身份 / 视图 / 流程 | 关 |

几个硬边界：

- **密码只写不读**。没有读密码、复制密码或返回明文的工具；密码进加密凭据库后就只在主进程内用于填充。
- 删除类工具即使开了权限，也必须显式传 `confirm: true`。启动类只受「运行」权限控制：
  打开窗口本身不改任何数据。
- 每次调用写一行审计日志（`mcp-audit.log`），密码、口令、Token 一律替换成 `[redacted]`；
  往密码框里输入的文本同样脱敏，哪怕参数名不叫 password。碰到页面的调用还会记下
  **来源**（origin），所以「AI 在这个站点上做了什么」可以直接从日志里读出来。
- **日常档案里 AI 默认只读**：那是你自己登录着的浏览器，所以 AI 只能读页面、截图、切标签；
  点击、输入、填表、跑流程都要你先允许这个来源（浏览器工具栏的盾牌按钮，或设置页）。
  账号页与干净会话不受限制——那本来就是给 AI 驱动的。同一个来源的 AI 操作次数会显示在
  运行栏对应那一行。
- **导航目标必须来自你或工作区**：空白页的首次导航、同页链接、已有的站点或书签地址都放行，
  但页面正文里写的地址不算数。这条防的是提示注入——一个被篡改的页面不能指挥 AI 去别处。
- 应用退出时先关 MCP 再回收浏览器，端口随进程释放，不会留下驻留服务。

## 导入导出

两种导出，用途不同。

**配置导出**（设置页 →「数据」）用于换机器：导出成一份 JSON，包含站点、身份、视图、标签、
流程与布局预设；浏览器 Profile 与登录态不导出（换机器本来就该重新登录）。

- 密码默认不导出。勾选「连同密码一起导出」后，密码会用你设置的口令经 scrypt + AES-256-GCM
  加密后放进同一个文件；导入时要输入同一口令，口令错误则整体拒绝，不会只导入一半。
- 导入按 id 合并：相同 id 覆盖，新条目追加；所属站点缺失的身份与视图会被跳过并计入结果。
- 导出文件不包含运行中实例与登录状态。

**账号包**用于把登录交给别人：在账号页点「选择账号」勾几个（也可以只勾半个站点），再点
「导出所选账号」，选要不要带密码与口令，得到一个小得多的文件。对方在 设置 →「数据」导入，
登录态立刻可用，不必重新注册一遍。

- 匹配不靠 id：站点按地址、账号按用户名。所以对方第一次见到这个站点也能导入。
- 带密码时同样用口令加密，复制文件的人打不开；口令错了整体拒绝。
- 只包含选中的站点与账号，不会带走你的视图、布局与其它站点。

## 托盘模式

默认开启：点窗口的关闭按钮只是隐藏到托盘，浏览器窗口与 AI 接入继续运行——
避免正在用 AI 建视图时误关应用导致连接断开。要从托盘菜单或设置页的「彻底退出」退出，
退出前会先停 MCP、再回收全部浏览器。

## 凭据安全

测试库常常是生产数据的副本，所以密码不能明文躺在磁盘上。

- 默认使用 Electron `safeStorage`：Windows DPAPI、macOS Keychain、Linux 系统密钥环
- 可以设置**应用主密码**：用 scrypt（N=32768, r=8, p=1）派生密钥，以 AES-256-GCM
  逐条加密，每条带随机 IV 与认证标签；vault 里只保存 salt、参数和密文
- 主密码模式下，启动后凭据库处于锁定状态，输入主密码才解密；可随时改密、立即锁定或改回系统密钥环
- 旧版本遗留的明文条目会在启动时自动重新加密
- 密码只在主进程内解密，不进入渲染进程、不写入日志；剪贴板复制 30 秒后自动清除

系统密钥环能挡住离线读取文件，但挡不住以你的账户身份运行的程序。主密码把这一层也补上——
这也是为什么它更接近密码管理器而不是「一个配置文件」。

## 引擎支持

| 平台 | 完整支持（CDP） | 外部模式 | 检测但不支持 |
| --- | --- | --- | --- |
| Windows | Edge / Chrome / Brave / Vivaldi / Chromium | Firefox | — |
| macOS | Chrome / Edge / Brave / Vivaldi / Chromium | Firefox | Safari |
| Linux | Chrome / Chromium / Edge / Brave / Vivaldi（含 Flatpak、Snap） | Firefox | — |

CDP 引擎支持自动填充、登录态检测与窗口平铺；Firefox 走外部模式，可多开、可布局、可复制密码，
但不接管页面。浏览器由系统安装和更新，Ensemble 不打包、不分发浏览器内核。

## 开发

要求 Node.js >= 22.12、pnpm 12。

```bash
pnpm install
pnpm dev        # 开发模式
pnpm verify     # 全量校验：类型 + 单测 + 结构契约 + 构建
pnpm test       # 单元测试
pnpm test:e2e   # 真实浏览器端到端（需要本机已安装 Chromium 系浏览器）
pnpm build      # 构建 out/
pnpm screenshots # 重新生成 README 截图（需先 build）
pnpm diagrams    # 重新生成 SVG 示意图（中英两版，无需 build）
pnpm dist       # 打包安装程序到 release/
```

首次安装 Electron 需要访问外网。国内网络可先配置代理：

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
pnpm install
```

如果 `pnpm install` 后 `node_modules/electron/dist` 不存在，单独重试下载脚本：

```bash
node node_modules/electron/install.js
```

## 技术架构

```
src/core/       纯 Node 层：引擎扫描、CDP 客户端、启动器、凭据、进程注册表
src/main/       Electron 主进程：窗口、IPC、safeStorage、系统集成、内置浏览器
src/preload/    受控 IPC 桥
src/renderer/   Vue 3 管理台界面与浏览器页
```

管理台与内置页面都由 Electron 承载：管理台是普通渲染进程，被测页面是主进程里的
`WebContentsView`，画在「浏览器」页的舞台区域上。外部表面则是真正独立的浏览器进程。
`src/core` 不依赖 Electron，可以在纯 Node 下测试。

主链路直接使用 CDP，而不是用 Playwright 托管人工窗口——Playwright 默认会接管对话框、下载和扩展，
会改变被测环境。

## 非目标

- 不做指纹伪装、反检测或自动化养号
- 不把内置表面做成 Chrome 平替：没有扩展商店、密码管理器与同步，也不做跨设备书签同步
  （本机书签是有的：一个名字加一个地址，跟着工作区导出导入）
- 不做用例管理、测试报告或 CI 平台
- 不支持 Safari 多开（Safari 没有独立的 profile 目录模型）
