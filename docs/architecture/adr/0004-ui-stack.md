# 0004. UI 栈：Reka UI + Lucide + CSS 变量

- 日期：2026-10-19
- 状态：已采纳

## 背景

项目要长期开源维护，界面需要精致、有辨识度，不能是标准 web 后台长相；同时表单与
弹窗需要可靠的无障碍与键盘行为。

## 决策

- 行为层：**Reka UI**（Radix 的 Vue 移植），零视觉样式。
- 图标：**Lucide**，线性风格，16px 清晰。
- 样式：**CSS 变量 token + Vue scoped CSS**，不引入 Tailwind。
- 表格：确有复杂表格需求时再上 **TanStack Table**（headless），不为了将来可能的需求提前引入。
- 设计方向：暗色精密仪表台为默认（暖金强调、1px 细线、等宽字体承载技术数据），
  浅色档案纸作为可选亮色主题，共用同一套语义 token。

## 被否方案

**Element Plus**：复杂控件齐全，但它的默认骨架（间距、圆角、阴影、蓝色主色、卡片布局）
就是「无聊后台」的标准答案。主题变量只能换颜色，改不了骨架，最后会花大量时间覆盖样式，
仍然看得出痕迹。

**纯手写无依赖**：视觉最自由，但 Dialog、Combobox、Tabs 的无障碍与键盘交互成本高，
容易出现焦点陷阱、`aria` 状态错误。

**Tailwind**：这个产品的组件数量不多但每个都要精雕，utility 串会让密集模板难读。
真有大量表单页时再局部引入。

## 后果

- 视觉文件集中，改主题只需改 token。
- 需要自己写样式，但没有和组件库打架的成本。
- 一旦引入带视觉主张的组件库，必须同时更新本 ADR，不允许两套设计语言混用。
