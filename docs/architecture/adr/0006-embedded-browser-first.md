# 0006. 内置浏览器为主、外部浏览器为保真校验

- 日期：2026-10-22
- 状态：已采纳（取代 [0002](./0002-electron-shell-not-embedded-browser.md)）

## 背景

0002 的结论是「Electron 只做管理台，被测页面交给外部真实浏览器」。它当时基于三个判断：

1. 内嵌页面的 UA 与指纹和真实浏览器不同，兼容性结论会失真；
2. 没有扩展、下载管理、真实品牌特征；
3. 外部窗口的自动化只能走 CDP，边界清晰。

这三个判断本身没有错，但它们回答的是**保真度**问题。实际使用中暴露了另一组需求，
0002 没有覆盖：

- AI 驱动测试时，每开一个账号就弹一个系统窗口，满屏窗口盖住工作区；
- 用户无法在 AI 操作过程中介入（填验证码、点一次确认），只能中断脚本重来；
- 关闭窗口后会话状态要重新建立，AI 每一轮都得预热；
- 截图、录制、并排对比这些动作在外部窗口上要处理窗口边框、遮挡、DPI、前台抢占，
  在 0.4 里为此付出了大量系统级代码（窗口几何、`AttachThreadInput`、进程刷盘等）。

2026-10-22 实测确认（Electron 44.9.0 / Chromium 152）：

- `WebContentsView` 支持按身份隔离的 `persist:` 分区，Cookie 互不可见；
- `webContents.debugger.attach("1.3")` 在不开放任何调试端口的情况下提供完整 CDP；
- 每个 view 都是标准 `page` target，Playwright `connectOverCDP` 可以直接接管；
- 截图在可见、可见但无焦点、最小化三种状态下可获取（最小化需退到 `capturePage()`）；
- DevTools 与 `findInPage` 都是 Chromium 原生能力，不需要自研。

也就是说，0002 里「Playwright 无法接管内嵌页面」这条已经不成立。

## 决策

浏览器分两种表面（surface），**内置为默认与主推，外部为保真校验**：

| | 内置（`WebContentsView`） | 外部（系统 Chrome/Edge/…） |
| --- | --- | --- |
| 可控性：截图、录制、接管、并排、布局 | 完整 | 受限 |
| 保真度：真实版本、扩展、DRM、企业策略 | 较弱 | 最强 |

- 日常操作、AI 驱动、权限对比、可见性断言、会话保持默认走内置。
- 需要确认「在用户真实环境里也是这样」时切到外部。外部模式只承诺保真，不承诺
  与内置相同的功能集。
- 两种表面共用同一套身份、凭据、场景与布局模型，区别只在承载方式。
- 一个身份在一次运行中只使用一种表面，不静默切换：切换意味着登录态要重建，
  必须由用户显式触发。

内置表面的硬约束：

1. `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`，远程页面不得挂任何 preload。
2. 每个身份一个 `persist:` 分区，分区名由身份 id 派生，禁止共用。
3. AI 控制通道走进程内 `webContents.debugger` 或已鉴权的 MCP，**默认不开放调试端口**。
4. UA 去掉 `Electron/x.y` 段，避免站点识别为非常规客户端。
5. 内置模式产出的结论标记来源；需要外部复核的结论不得只凭内置结果下判断。

## 被否方案

**只做内置、删掉外部模式**：内置回答不了「真实用户环境里是否也这样」。扩展依赖、
DRM 内容、企业证书策略、特定浏览器版本的行为差异，只有外部真实浏览器能给答案。

**继续只做外部、不做内置**：即 0002 的原决策。它无法解决弹窗打扰、人机接力、
会话预热和截图成本，也无法支持录制。这四条正是 AI 优先场景的核心。

**自研 Chromium 分支**：能完全控制，但要长期承担 Chromium 升级、安全补丁、编解码、
扩展商店与签名分发，与产品定位不匹配。

**把内置页面当作指纹隔离手段**：内置分区只隔离 Cookie 与存储，不做指纹伪装。
项目仍不提供 canvas / WebGL / 字体列表伪造。

**默认开启远程调试端口供 AI 连接**：端口无鉴权，本机任意进程都能驱动浏览器。
默认走进程内通道；需要给外部脚本开放时，必须显式开启并接受风险。

## 后果

- 安装包体积不变：Electron 运行时本来就在包里，内置浏览器不增加内核。
- 内置模式下 0.4 为外部窗口写的窗口几何、前台抢占、进程回收代码不再参与主链路，
  但保留给外部模式。
- 内置与外部各自维护登录态。切换表面需要重新登录一次，依赖自动填充降低成本。
- 新增需要长期跟进的事项：Electron 升级节奏决定内置内核版本；扩展、DRM、下载管理
  在内置模式下缺失，需要在界面上明确标注能力边界。
- 测试策略变化：内置表面可以用进程内 CDP 做自动化；外部模式仍按原有 E2E 覆盖。
