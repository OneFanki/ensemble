# 0007. 站点与视图模型：环境改名站点、场景改名视图、站点标签

- 日期：2026-10-22
- 状态：已采纳；其中「站点是全局作用域」「标签仅用于站点」两点已被
  [0008](./0008-sites-as-login-recipes.md) 修订

## 背景

现在的三层模型是「环境 → 身份 / 场景」。实际使用中暴露出两个问题。

**一、「环境」同时承担了两件不同的事。**

- 分类分组：身份和场景都挂在它下面，是界面的切换单位。
- 站点配置：`baseUrl`、`loginPath`、`authCheckPath`、`autoSubmit`、`extraFields`、默认密码。

第二件事本质上是「一个应用」的属性。所以用户看到的「环境」其实就是一个站点。

**二、前置步骤太多。**

新建一次验证要先建环境、再建身份、再建场景。复杂场景下这个结构是对的，
但简单场景（就想同时看两个账号）要过三道门，新用户打开就流失。

考虑过在环境里插入一层「站点」（环境 = 部署，站点 = 应用），能解决跨部署复用，
但代价是：

- vault 的加密键要跟着下沉，迁移出错会丢密码；
- 概念从三层变四层，与简化目标相反；
- 只覆盖有多应用需求的少数用户。

## 决策

### 1. 环境改名站点，不改变数据结构

`Environment` → `Site`。字段、id、存储位置全部不变。

**vault 键与 profile 目录（`<siteId>/<identityId>`）一个字不动。** 内部标识符不需要和
界面用词一致，为了「名字统一」去动加密数据的键，只增加风险。

站点 = 一个地址 + 一套登录配置。身份归属于站点；登录态是站点级的（Cookie 域）。
「同一账号要测两个地址」仍然是两个身份，因为 Cookie 域不同。

### 2. 站点标签，只用于归类

站点可以打多个用户自建的标签（多对多）。标签是纯展示结构：

- 站点页按标签分组，可搜索；
- 标题栏的站点切换器按标签分组；
- 删除标签只解除关联，站点与账号都不受影响；
- 标签不参与任何业务规则。

> 2026-10-22 修订（[0008](./0008-sites-as-login-recipes.md)）：标签升级为一套全局命名空间，
> 账号与视图也能挂；标题栏的站点切换器已删除，站点不再是全局作用域。

**不重新引入「环境」层。** 将来若真需要在一个部署下配多个应用，用标签归类即可，
不需要新的层级。

### 3. 场景改名视图，并明确它是什么

`Scene` → `View`。

> **视图 = 一份保存的定义 + 至多一个打开的容器。**

- 没打开时：它是「要启动哪些账号、用哪个布局」的模板。
- 打开后：它是浏览器里的一块共享屏幕区域，标签页是它的成员。
- 一个视图可以跨站点，成员来自不同站点。
- 重复打开同一个视图：不新建容器，补齐缺少的标签（已有的不重建，登录态保住），
  然后切过去。

「视图」同时指定义和容器不是含糊，而是同一个东西的两个状态——像文档在磁盘上和在
编辑器里都叫文档。

### 4. 视图与分屏是同一件事

视图不是为了「归类」，而是「这几个页面共享一块屏幕」。

- 不建视图时就是普通浏览器：一行扁平标签，一次看一个页面。
- 视图由运行栏的「创建视图」按钮显式创建，再把标签拖进去；拖拽本身只排序或加入已有视图
  （默认 2×1，落点决定左右还是上下）。
- 视图内可以切分布局：内置六档 + 用户自定义预设。
- 视图不会因为只剩一个标签而自动解散；空视图保留，直到手动关闭。

> 2026-10-20 修订：最初的设计是「把两个标签拖到一起就组成视图、只剩一个标签自动解散」。
> 实际使用中，滚动条会让「拖到空白处」不可达，自动建组也容易因落点偏差误触发，因此改为
> 一律手动创建、容器不自动回收。

### 5. 自定义布局接入内置表面

`embeddedSlotRects` 目前只认内置布局，改成接受 `LayoutPreset`，与外置窗口共用同一份
几何计算。两条表面本来就应该用同一套槽位。

## 被否方案

**在环境里插入站点层（环境 = 部署，站点 = 应用）**：见背景。否决理由是迁移加密凭据
的键风险高，收益只覆盖少数多应用用户，且与「减少前置概念」的目标相反。

**保留「环境」这个名字**：它同时暗示「分组」和「站点」，两个含义会持续误导——用户会
以为可以往一个环境里加第二个地址。

**取消视图、只保留扁平标签页**：多个场景、多套部署的页面会混在一个列表里，无法表达
「这四个属于这块四宫格」。

**视图做成真实的引用（跨站点共享同一份成员）**：成员是「站点 + 账号」，跨部署复用
需要知道哪个站点对应哪个站点，等于把砍掉的那层换个名字装回来。用复制 + 账号引用来接，
见下方「跨站点复用」。

**只同步凭据、不同步角色等展示字段**：会让界面无法解释「这个字段为什么能改、那个不能」。
引用就是完全一致，要改就断开——角色本身只是标签，同步它不带来任何行为风险。

**另设「安全码」作为复制 / 引用的闸门**：安全码由应用自己校验，能改配置文件的人同样能
绕过，收益接近心理安慰。真正的缺口是站点地址可变，改用 origin 变更检测。

## 跨站点复用（本轮结论）

两种表面下的同一个痛点：本地验证过的一套流程，要在测试部署再跑一遍。

### 账号：引用为默认，可断开为独立副本

身份由两部分组成，只有前半部分可以跨站点共享：

| 部分 | 跨站点 |
| --- | --- |
| 用户名、密码、显示名、角色、颜色、备注、额外登录字段 | 共享 |
| id、所属站点、profile 目录、会话分区、登录态、启动路径、引擎 | 每个站点各有一份 |

后半部分与站点绑定：Cookie 属于域，分区按身份 id 建立，物理上无法共享。所以「引用」
共享的是用户填写的账号资料与密码，不是会话。

身份增加 `credentialFrom`（来源站点里的身份 id）与 `passwordMode: "reference"`：

- 被引用字段在引用方只读，界面显示来源链接；
- 只允许一层引用，被引用者自身不能是引用，避免环；
- 引用方的登录态、健康检查、profile 完全独立；
- 启动路径与引擎保持本地——同一个账号在不同站点的入口与浏览器选择可以不同；
- 来源的用户名或密码变更不会让引用方已建立的登录态自动失效，需要重新检测一次。

**引用与复制是同一机制的两种状态**：引用是默认；复制 = 断开引用。断开时把当前解析出的
密码与全部同步字段落成本地值（密码写为 `custom`，不回退到本站点默认密码），之后各改各的。
只需要实现引用与「断开」两个动作，不需要两套创建流程。

**引用 = 完全一致。** 想改角色、颜色或备注，就断开。不做「部分字段同步」——那会让界面
无法解释「这个字段为什么能改、那个不能」。

删除来源身份时，把解析值物化到所有引用方并自动断开，避免留下无法启动的悬空身份。

### 视图：跨站点复制时用引用接账号

视图成员是身份 id，所以把视图复制到另一个站点时，逐个成员在目标站点上找对应身份：

- 目标站点已有同名账号 → 视图直接使用它（不建引用，也不复制凭据）；
- 目标站点没有 → 在该站点上建一个引用身份，凭据指向来源站点的那一个，登录态各自独立；
- 用户也可以选择跳过某个成员。

副本记录 `copiedFrom: { siteId, viewId }`，视图页提供「从来源同步」的手动动作——拉取
来源的成员与布局，重跑一遍匹配。它是显式动作，不是实时联动。

这样「本地跑过的一套流程搬到测试部署」只需要一次复制：账号引用过去，两边密码一改就同步，
要各改各的就断开引用。

### 为什么视图成员不做实时引用

视图成员是「站点 + 账号」。要在一套部署上复用、在另一套上也能跑，视图本身就得知道
「后台系统-本地 → 后台系统-测试」这种站点对应关系。那个对应关系就是环境层，或者需要
把站点标签升级成有语义的部署族。无论哪种，都是把刚砍掉的概念换个名字装回来。

复制把这份复杂度留在一次性操作里，而不是常驻在数据模型中。真到了「三套部署每天同步」
的程度，再评估要不要显式引入部署映射表。

## 凭据安全：地址变更是真实缺口

自动填充的跨域校验是「页面 origin 等于站点 baseUrl」。`baseUrl` 本身可编辑，所以把地址
改成另一台服务器，下次启动就会把密码填过去。这与复制 / 引用无关，是现有模型的缺口——
因此不能用「引用会扩大攻击面」作为否决理由。

修正：**记住每个站点最近一次使用的 origin**，与当前 origin 不一致时，在填充密码前要求
一次显式确认（SSH `known_hosts` 的做法）；确认后更新记录。

它不防本机攻击者——能改 `workspace.json` 的人也能删掉这条记录。它防的是误操作与
「悄悄改地址」这类难以察觉的改动，成本低、不引入新概念。相比另设一个「安全码」更实在：
安全码同样由应用自己校验，改文件即可绕过。

## 后果

- 数据迁移是字段重命名：`environmentId` → `siteId`、`scenes` → `views`，id 值不变。
- 身份新增 `credentialFrom` / `passwordMode: "reference"`，旧数据默认为 `inherit` 或
  `custom`，不加迁移步骤。
- vault 与 profile 目录不变，旧工作区可直接打开。
- 站点新增 `lastOrigin`，用于地址变更检测。
- 导出格式版本 +1，同时保留读旧版；导出时引用关系保留，引用方不携带明文密码。
- MCP 保留旧工具名作为别名，新增站点与视图工具。
- 全仓代码改名（`Environment` → `Site`、`Scene` → `View`），机械但面广。**单独一次提交
  完成，不与新功能混在一起**，否则出问题时无法区分是迁移错了还是功能写错了。
