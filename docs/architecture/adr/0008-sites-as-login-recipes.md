# 0008 · 站点降级为登录配方，标签升为全局

- 状态：已实施（0.5 开发版）
- 日期：2026-10-22

## 背景

0.4 的模型里站点（原名「环境」）是一个**全局作用域**：标题栏有一个站点切换器，账号页
和视图页只显示「当前站点」的内容。这个假设在引入内置浏览器之后开始失效，实测下来有三处
说不通：

1. **内置浏览器不认它。** 地址栏可以输入任何 URL，新标签是空白的，不会自动进入「当前
   站点」。于是「当前站点」只过滤管理列表，不影响真正打开的那块屏幕。
2. **视图已经跨站点。** 视图编辑器列的是全部账号，也允许保存跨站点成员；但视图列表又按
   当前站点过滤，结果有的视图按定义在那里、界面上却看不见。
3. **它是 0.4「环境」概念的残留。** 启动用的是身份自己的 `siteId`，从未读过全局选择。

同时用户提出两个相邻需求：手动登录后保存账号（类似浏览器密码气泡），以及「浏览器应该有
书签，书签就是站点」。

## 决策

### 1. 删除全局「当前站点」

- 标题栏的站点切换器删除，`setActiveSite` 删除。
- `settings.lastSiteId` 保留，但降级为「最近使用」，只作为新建账号/视图的默认值。
- 账号页列出全部账号，**按站点分组**；顶部可按运行状态、过期状态与标签筛选。
- 视图页列出全部视图；可按「包含的站点」「包含的标签」筛选。
- 会话健康中心默认覆盖全部账号。

### 2. 站点 = 登录配方 + 归属

站点保留这些字段，全部与「怎么登录、算哪个组织的账号」有关：地址、登录路径、检查路径、
默认密码、默认引擎、额外表单字段、标签。它不再回答「现在看哪些数据」。

站点页的每个卡片提供「打开站点」，把登录页作为新标签打开。

### 3. 一套全局标签

`SiteTag` 改名为 `Tag`，`WorkspaceData.siteTags` 改为 `tags`；`Site.tagIds` 保留，
`Identity` 与 `View` 新增 `tagIds`。

筛选语义（派生，不落库）：

- 账号的标签 = 自己的 + 所属站点的；
- 视图的标签 = 自己的 + 成员账号的 + 成员所属站点的。

删除标签时三处引用一起解除，实体本身不动。旧工作区文件里的 `siteTags` 直接按 `tags`
读出，同一个 id 与颜色，无需迁移脚本。

**不重新引入「环境」层。** 环境就是一组标签（生产 / 测试 / 客户 A）。多对一的分组用
标签就能表达，加一层只会把已经砍掉的层级换个名字装回来（见 ADR 0007 的被否方案）。

### 4. 站点即书签

不新增「书签」实体。站点本身就是书签，三个入口共享同一份列表：工具栏新建标签的分叉、
运行栏「标签页」块的 ＋、地址栏输入站点名时的补全建议。

「从站点打开」提供两种落点：干净打开（`persist:embedded-clean`）与用某个账号打开
（该账号的分区，登录态已在）。

### 5. 打开账号 = 默认标签组新开一页

单点账号页的卡片，**永远在默认（扁平）标签组新开一个页面**，不看台上有没有视图，也不看
这个账号是否已经开着。批量启动是唯一例外：它本来就是「一次看很多」，所以按默认布局新建
一个视图。

要让某个页面出现在视图里，路径只有两条：把标签拖进去，或在视图里用「+」选中账号。

### 6. 登录捕获

内置页面里手动登录后提示保存。密码经 CDP `Runtime.addBinding` 从页面直达主进程，
渲染层只拿一次性 token、用户名和来源；点保存时表单带 token，主进程取密码写库并销毁 token。
按 origin 匹配站点；没有匹配就在表单里就地新建站点，避免「站点不存在所以密码丢了」。

## 被否方案

**保留全局站点选择，改成「内置浏览器跟随它」。** 那样每开一个空白标签都得先决定它属于
哪个站点，而空白标签的意义恰恰是「还没决定去哪」。而且同一屏上的视图可以跨站点，一个
全局值无法描述当前屏幕。

**新增独立「书签」实体（名称 + URL）。** 那就是再来一份站点：地址、登录路径、默认密码
都要重新填一遍，两处会漂移。站点已有的信息足够当书签。

**把标签分别建三套（站点标签 / 账号标签 / 视图标签）。** 用户会在三个地方创建同名同色的
标签，然后困惑为什么筛选不到。命名空间统一，语义靠「匹配自己的 + 上下文的」推导。

**账号打开总是替换选中格（浮动加载到选中位）。** 连续打开多个账号时会把同一格反复替换，
用户看到的是「只有一个变了」。

**账号打开按落位矩阵填空位、满了进台下。** 这条曾经是本 ADR 的规则，实践里不行：用户点一张
卡片的意思是「给我开这一页」，而矩阵把这次点击变成了布局操作——台上的视图被加了一格、
挤出别人。账号页不是一个布局界面，它不该改舞台。落位矩阵的初衷（连续启动时别互相覆盖）
由批量启动承担：那是一次明确的「铺开」动作，所以它自己建视图。

**登录捕获做成浏览器扩展。** 项目明确不做扩展形态；内置表面是主界面，用它自己的 CDP
通道就够，且密码不必经过渲染层。

## 影响

- 数据：`siteTags` → `tags` 键改名（向后兼容读）；`Identity`/`View` 增加 `tagIds`。
- API：`saveSiteTag`/`deleteSiteTag` → `saveTag`/`deleteTag`；`SiteTag` →
  `Tag`，`SiteTagDraft` → `TagDraft`。
- 视图：`launchView` 不再拒绝跨站点；`launchGroup` 接受一个按成员解析站点的函数。
- 主进程新增 `findSiteByOrigin`、登录捕获存储与 `Runtime.addBinding` 注入。
- 界面：标题栏只剩品牌与启动目标；侧栏底部显示工作区计数；账号页分组、视图页筛选；
  标签管理独立一页（全局命名空间不挂在站点页下；最初放在设置里，后来移到左侧导航，
  因为它是每天都要碰的东西，不是配置项）。
