# 0013. MCP 工具面按表面分族，旧名字留作隐藏别名，名字猜错给建议

- 日期：2026-11-24
- 状态：已采纳（细化 [0006](./0006-embedded-browser-first.md) 在 AI 接入上的落法）

## 背景

0006 把浏览器分成内置与外部两种表面。落到 MCP 工具上时，`launch_view`、`launch_identity`、
`launch_clean_session` 三个工具各带一个 `external` 开关：不传开在内置浏览器，传了开系统
浏览器。一个工具两种性格，连返回的东西都不同（标签页 id 变成窗口 id）。一次真实事故里，
AI 把本该在内置页面里完成的校验开进了系统浏览器。

2026-11 对全部工具逐个审查，同类问题还有一批，单看每条都像小事，合起来的代价是调用方
没法凭直觉猜对任何一处：

- 省略 `tabId` 落到用户正在看的页面上（AI 开的页不上台，不是「激活页」）；
- 描述点名的参数在 schema 里不存在；同一件事三个字段名（`text` / `elementText` / `expect`）；
  装着标签页 id 的参数叫 `beforeOrAfter`；
- 对象专属工具有的收 `id`、有的收 `identityId`；页面在别处叫标签页，这里叫 `pageId`；
- 列表类返回有的裸数组、有的包一层；成功信封有 `{ok}` / `{deleted}` / `{stored}` /
  `{stopped}` 四种写法；
- 名字猜错只得到一句「没有这个工具」。

## 决策

1. **内置与外部分成两族工具。** 页面工作全在内置浏览器（`open_browser_*`、`*_browser_*`）。
   外部系统浏览器只有一个入口 `launch_external_browser`（账号 / 视图 / 干净身份三选一），
   配 `stop_external_browser`、`stop_all_external_browsers`；它的窗口 AI 驱动不了。
2. **旧名字留作隐藏的兼容别名。** `LEGACY_TOOL_NAMES` 列出旧名与规范名；别名继承规范工具的
   档位、闸门与结果格式，`tools/call` 时转交，但不出现在 `tools/list` 里。
3. **参数的旧名字作为别名接受。** 入参一律把对象写进名字（`identityId` / `viewId` / `tabId`…），
   `argumentAliases` 在入口校验之前把旧名换成规范名；别名与规范名同给且都有值时拒绝。
   两字段合成一字段的旧写法（`ownerKind + ownerId`）用 `normalizeArguments` 钩子。
4. **默认值取「调用方最可能指的那个」，拿不准的方向不留默认。** 省略 `tabId` 指 AI 最近
   打开的页面；`set_browser_layout` 省略 `viewId` 只收 AI 自己的页面；`handle_browser_dialog`
   的 `accept` 必填；`close_browser_view` 默认只关 AI 侧打开的页面。
5. **返回形状只有三种**：列表类以集合名包装，动作类 `{ ok, …事实 }`，其余直接返回对象。
6. **名字猜错了给建议。** 工具名对不上时报错里列出最相近的几个；参数名对不上时点名该工具
   真正的字段（`core/util/name-suggestions.ts`）。
7. **约定由契约测试守着**：`tests/contracts/tool-surface.test.ts`（命名、入参、档位、描述里
   点到的名字必须存在）、`ai-guidance.test.ts`（两族工具的选路语义）。

## 被否方案（必填）

- **保留 `launch_*` 的 `external` 开关，只把描述写清楚。** 描述写得再清楚，一个工具两种
  返回形状的事实不变；每个会话都要为三个几乎重复的工具付上下文。否。
- **直接删掉旧名字，硬切。** 调用方是已经配好的客户端、提示词与脚本，硬切等于把成本转嫁
  给它们；而兼容的成本只是一个对照表。否。
- **把旧名字也广播出去，各带一句「等同 X」。** 模型无法在两个名字之间做有用的选择，只会
  被迫多读三份描述。兼容别名不广播。否。
- **AI 没有自己的页面时，省略 `tabId` 直接报错。** 「对用户正在看的这一页动手」是内置浏览器
  的正当用法，来源闸门已经管住了默认身份里的输入。保留退回激活页。否。
- **省略 `tabId` 一律指「AI 最近操作过的页面」（含显式传 id 的操作）。** 规则更难解释，也
  多一份状态；最近「打开」的页面已经覆盖了绝大多数情形。否。
- **`set_browser_layout` 没有台上视图时直接报错。** AI 把自己开的几个页面摆成一屏是它用
  这个工具的主要理由；只收它自己的页面就没有副作用。否。
- **`handle_browser_dialog` 的 `accept` 默认 `false`（安全方向）。** 省略与显式写 `false`
  在返回里无法区分，调用方以为点了确定却什么也没发生；必填让歧义在入口就暴露。否。
- **`pop_out_browser_tab` 保留开关语义，在描述里写明。** 开关在脚本里的第二次调用会撤销
  第一次，描述写明也挡不住。否。
- **登录检测问不到内置页面时，退回外部浏览器那套登录状态作答。** 那是另一套 Cookie 的
  状况，答得再确定也是答非所问；如实回 `unknown`。否。
- **给快照每个节点附一份「定位提示」。** 节点已经有稳定的 `selector`；真正断链的是名字取错
  与同分时标签胜出，修那两处即可，不必让每份快照都变胖。否。

## 后果

- 工具列表里的名字与 `docs/engineering/ai-tools.md` 的总表必须一致，改名的旧名字记在该文档
  「旧名字对照」里。
- 新增工具时：内置工具名字里带 `browser`；外部工具名字里带 `external`；入参用带对象名的
  id；观察类进 `read` 档，会丢弃页面状态或往页面输入的工具过来源闸门。
- 兼容别名只增不减，除非发大版本；别名指向的规范工具必须是对外广播的工具，契约测试会查。
- 不兼容的返回形状变化（列表包装、`ok` 信封）与默认值变化记在 CHANGELOG 的「不兼容变更」
  里，由版本号体现。
