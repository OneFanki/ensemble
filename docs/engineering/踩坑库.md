# 踩坑库（Known Pitfalls）

> 遇到报错、现象诡异、行为不符预期时，先查这里再排查。坑是经验型知识：不进 README、
> 不进架构文档，只在这里按条目累积。
>
> 维护规则：解决后当场追加条目（含日期）；失效条目标记 `状态: 已过时` 并注明原因，
> 不删除。代价高的坑（数据损坏、账号串号、凭据泄漏、进程失控）解决后，必须同步升级为
> `AGENTS.md` 硬约束。

## 条目格式

```markdown
### <现象一句话>

- **环境**：<版本/平台/场景>
- **原因**：<根因>
- **解决**：<可复现的操作步骤>
- **日期**：YYYY-MM-DD
- **状态**：有效 / 已过时（原因）
```

## 浏览器启动与 CDP

### 场景启动失败：`启动 Microsoft Edge 失败：fetch failed`

- **环境**：Windows 11，Edge 155，Electron 44，CDP 启动方式
- **原因**：profile 目录里残留上一次运行写下的 `DevToolsActivePort`。新实例启动瞬间读到了旧端口，旧端口已经没人监听，`/json/version` 直接 fetch 失败。
- **解决**：启动前主动删除 `<profileDir>/DevToolsActivePort`；读取后不要只信文件内容，必须同时探活 `http://127.0.0.1:<port>/json/version` 才算就绪。
- **日期**：2026-10-19
- **状态**：有效（已修复并落地）

### 抓到的页面是 `about:blank`，注入脚本无效

- **环境**：Chromium 系浏览器，`--remote-debugging-port=0`
- **原因**：浏览器启动后先出现 `about:blank` 目标，随后才创建真正加载 URL 的页面。直接取 `/json/list` 第一项会拿到空白页。
- **解决**：`waitForPageTarget` 优先选择 `url !== "about:blank"` 的目标，超时后再退化为第一项。
- **日期**：2026-10-19
- **状态**：有效（已修复并落地）

### 原生 `confirm` / `alert` 被自动取消

- **环境**：任何用 Playwright 驱动人工操作场景
- **原因**：Playwright 文档明确：没有注册 `dialog` 监听时，所有对话框自动 dismiss。
- **解决**：人手操作的窗口不要交给 Playwright 托管。用系统浏览器 + CDP，只启用 Page/Runtime 的必要域，不接管 dialog。下载同理：Playwright 默认落到临时目录且 context 关闭即删除。
- **日期**：2026-10-19
- **状态**：有效（架构级约束，禁止回退）

### 浏览器没开远程调试，但也没有报错

- **环境**：企业统一管理的 Chrome / Edge
- **原因**：Edge 策略 `RemoteDebuggingAllowed=0` 会禁用 `--remote-debugging-port`，或安全软件拦截本地端口。
- **解决**：拉起后等 `DevToolsActivePort` 超时，给用户明确提示「可能被企业策略阻止」，并允许改为外部模式。不要静默卡住。
- **日期**：2026-10-19
- **状态**：有效

### 浏览器版本自动升级后 profile 行为异常

- **环境**：系统 Chrome / Edge
- **原因**：profile 格式随大版本迁移，通常单向，不支持可靠降级。
- **解决**：升级前备份 profile 元数据；出问题时新建 profile 重新登录，不要试图把 profile 降级。需要可复现版本时，单独用固定版本 Chromium，不替换系统浏览器。
- **日期**：2026-10-19
- **状态**：有效

### 便携版冷启动比安装版慢一秒多

- **环境**：electron-builder portable target，Windows
- **原因**：portable 产物是一个自解压程序，每次启动都先把 Electron 运行时解压到
  `%TEMP%\<随机目录>` 再拉起主进程，解压本身就要一秒左右，且每次都是冷目录。
- **解决**：日常使用装 `setup.exe` 或直接跑 `win-unpacked\Ensemble.exe`；便携版只用于临时
  试用。判断当前在跑哪种形态，看进程命令行路径是否在 `%TEMP%` 下。
- **日期**：2026-10-19
- **状态**：有效

### 首次启动慢：窗口在等引擎扫描和进程清理

- **环境**：启动时同步执行 `scanEngines()` 与 PowerShell 进程枚举
- **原因**：`Get-CimInstance Win32_Process` 单次约 1.1 秒；引擎探测又要串行跑注册表查询
  和版本探测。这些都在 `createWindow()` 之前，用户看到的是几百毫秒到两秒的空白。
- **解决**：`initialize()` 只读本地 JSON 与引擎缓存，立刻建窗口；进程清理与引擎扫描放到
  `startBackgroundMaintenance()` 后台执行，完成后广播。缓存文件 `engines.json` 记录上次
  扫描结果，启动时先用缓存，再静默刷新。注册表查询和版本探测改为并发。
- **日期**：2026-10-19
- **状态**：有效（已落地）：安装形态二次启动约 660ms，首次约 1.3s

### 右下角 toast 被裁成两截：fixed 锚点被祖先 transform 劫持 + 文字不可断行

- **环境**：Windows，Electron 44，125% 显示缩放，8 账号批量启动后的登录失败 toast
- **现象**：toast 卡片被画成 dock 的宽度（像素扫描：卡片左缘 = dock 左缘、右缘 ≈ 窗口右缘），
  卡内文字比卡片宽，从卡片两侧内缘裁断，只见「…04」的尾巴和「请手动接」的半句。
- **原因**：`.toast-stack` 是 `position: fixed; right: 18px`，但 fixed 只有在**祖先链上没有任何
  transform / contain / will-change** 时才以视口为包含块。某个祖先一旦带上了，锚点整体改挂到
  那个祖先，堆栈宽度跟着变成祖先的可用宽度；再叠加文字不可断行（min-content 超过 max-width
  时 flex 子项会击穿它），文字就溢出卡片两侧。劫持者是条件性出现的（复现会话里父链干净，
  offsetParent 为 null），所以无头复现稳定不出现——修法必须「整个类」消灭而不是找单个劫持者。
- **解决**：`<Teleport to="body">` 把 ToastStack 挂到 body（项目惯例，ComboBox/BookmarkGrid
  同款）——body 之后没有祖先，锚点不可能被偷；令牌定义在 `:root`，teleport 不丢样式。另把
  `max-width: 380px` 收紧为 `min(380px, calc(100vw - 36px))`，不可断行的极长文本也出不了视口。
  回归：`e2e-toast-geometry.mjs`（8 项）——以 `offsetParent === null` 作为「锚点未被劫持」的
  直接判据，并断言右缘距视口 18px、整堆在视口内；跑在 2048×1222 + dpr 1.25（用户缩放）下。
- **教训**：① `position: fixed` 的「相对视口」是有前提的，浮层一律 Teleport 到 body；② 复现
  不出来不代表没 bug——劫持条件在用户的会话状态里，回归断言要盯机制本身（offsetParent）而
  不是某个复现路径。
- **日期**：2026-10-31
- **状态**：有效（已落地）

### 扁平舞台弹 HTML 弹层时，页面整体上移一个标签条高度

- **环境**：Windows，Electron 44，内置表面扁平模式（无布局 / 松散标签，带实例标签条）
- **现象**：点「+」或右键菜单等会弹 HTML 弹层的入口，弹层底下的冻结截图比实况页面高出一截
  （位移 = 26px 头带），弹层关闭后恢复。
- **原因**：`freeze()` 的扁平分支用原始 `stage` 当截图矩形，注释还写着「扁平模式没有头带」——
  那是 2026-10-26 给扁平舞台加实例标签条之前的旧事实。实况摆放（`applyLayout` 扁平分支）用的
  是 `embeddedViewRect(stage)`（顶部让出 26px），冻结截图却从 `stage.y` 画起。多格路径用的是
  `embeddedViewRect(slot)`，所以只有扁平模式中招。
- **解决**：扁平分支同样过 `embeddedViewRect(stage)`，与实况摆放共用同一个几何函数。守则：
  **冻结矩形与摆放矩形必须出自同一个函数**，凡是给摆放加几何偏移的地方，同步检查 `freeze()`。
  回归：`e2e-overlay-freeze.mjs` 新增「扁平冻结矩形 == 实况视图矩形」断言（7 项）。
- **日期**：2026-10-30
- **状态**：有效（已落地）

### 引擎版本号显示为 `-`

- **环境**：Windows，Edge / Chrome
- **原因**：Edge 与 Chrome 的可执行文件固定在 `Application\msedge.exe`，版本号在**同级
  的版本目录**里（如 `Application\155.0.4283.62\`）。`versionFromExecutablePath` 读的是
  父目录名，取不到。另外这两个浏览器执行 `--version` 在 Windows 上不输出任何内容。
- **解决**：新增 `versionFromSiblingFolders()` 读同级的最大版本目录名；Firefox 这类没有
  版本目录的，用一次批量 PowerShell 读 `VersionInfo.ProductVersion`。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 停放页满速白烧资源：CPU 节流与 hide 都停不掉 rAF，真睡眠是 lifecycle frozen；扫描必须构造时启动

- **环境**：Windows，Electron 44 / Chromium 152，内置表面多账号 + 重页面（3D 首页）
- **现象**：同时跑多个账号时，看不见的停放页（含 3D 场景）依然满速渲染，GPU/CPU 持续被吃；
  Chromium 原生后台节流完全没生效。
- **实测四个事实**（离屏 harness + 同 partition 读者页信标，全程不触碰被测页）：
  1. 停放 = 把视图 `setBounds` 到窗口右缘外。Chromium 的可见性判定不含「子视图在窗口客户区
     外」，页面仍是 visible，`backgroundThrottling`（默认本就开着）永不触发——**前提是应用
     窗口本身在屏上可见**；整个窗口被盖住/移出屏幕时，窗口级遮挡节流会把一切（含台上页）压
     停，这层是 Chromium 送的，不需要我们做。
  2. `Page.setWebLifecycleState: "frozen"` **真挂起 JavaScript**：冻结页上 `Runtime.evaluate`
     永不返回（executeJavaScript 超时实测）。2026-10-30 曾记录「frozen 只浅冻结、rAF 照跑」，
     **那轮测量被污染了**——当时的读数通道走 `EmbeddedCdp.send`，其唤醒钩子会先把页面解冻再
     执行，测到的是解冻后的活页。以本条为准。
  3. `view.setVisible(false)` 连 `document.visibilityState` 都不变（仍 "visible"），JS 照跑、
     rAF 照跑（读者页信标实测）。（`setFrameRate` 仅 offscreen 渲染生效；
     `setVisible(false)` 唯一的实际效果是 compositor 停出帧——这正是当年「CDP 截图卡死」的
     原因，capturePage 仍可用。）
  4. `Emulation.setCPUThrottlingRate` 只拖慢任务调度，rAF 由 compositor 驱动，对 GPU/帧循环
     为主的开销不成比例；作为「睡眠」杠杆被 frozen 取代。
- **解决（2026-10-31 定稿）**：`aiIdleFreeze` = 10 秒扫描，停放页闲置 60 秒（窗口期内无 CDP
  流量）即 `lifecycle "frozen"`（JS 全停，3D 场景随之停）；AI 每条命令在 `EmbeddedCdp.send`
  **await 唤醒**（lifecycle "active"）再执行；回台/导航/刷新也唤醒。豁免：台上/加载中/崩溃/
  空白/有声/带 DevTools。headless 运行整体关闭。
- **⚠️ 第二个坑（1.3.0 实际踩的）**：扫描最初是**惰性启动**（第一次 CDP 命令才建 interval），
  而 CDP 命令只有 AI 才发——纯手工使用的会话里扫描从未运行，降速一次都没发生。扫描必须在
  构造时无条件启动。
- **测量陷阱**：测每页机制时，窗口被盖住/移出屏幕会让遮挡节流淹没一切读数——「测不出差异」
  不等于机制无效； harness 的窗口必须真实可见地摆在桌面上。
- **日期**：2026-10-30（2026-10-31 二次修正：更正被污染的 frozen 结论、换杠杆、修扫描启动）
- **状态**：有效（已落地；最终实机确认待窗口可见的多账号场景）

## 界面与可读性

### 弹窗打开时 toast 被遮住

- **环境**：Reka UI Dialog + 自定义 toast
- **原因**：toast 容器 `z-index: 60`，而 Dialog 的遮罩是 70、内容层是 71。错误提示在
  编辑弹窗里触发时正好被压在最下面，用户只看到一片模糊背景。
- **解决**：toast 是全局反馈，层级必须高于任何模态层。统一约定：遮罩 70、弹窗 71、
  toast 100、系统级提示更高。新增浮层时先对齐这张表，不要各自取号。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 保存时提示 `An object could not be cloned`

- **环境**：Electron IPC，Vue 3，`contextBridge`
- **原因**：弹窗里的表单是 `reactive()` 对象，它的嵌套数组与记录仍是 Proxy。IPC 用结构化
  克隆序列化参数，遇到 Proxy 直接抛这个错。只在「先打开弹窗再保存」的真实路径出现，
  直接用普通对象调 IPC 反而正常，很容易漏测。
- **解决**：发 IPC 前把 draft 转成纯数据（`JSON.parse(JSON.stringify(v))`）。draft 本来就是
  JSON 形状，round trip 没有信息损失。约束：渲染层传给主进程的参数必须是可结构化克隆的值。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 拖拽标签页「看起来在拖，松手什么也没发生」

- **环境**：Electron 44 + Vue 3，`ref()` 持有的拖拽落点对象直接当作 IPC 参数
- **原因**：`ref({...})` 的值是深响应式的，读出来的 `dropHint.value` 是 Proxy；它作为
  `ipcRenderer.invoke` 的参数被结构化克隆时抛 `An object could not be cloned`。异常发生在
  `drop()` 处理器里，界面高亮（由同一对象驱动）完全正常，所以表现是「拖拽完全没反应、
  控制台也不报警」——只有渲染进程的 `console.error` 里能看到一句。
- **解决**：落点这类要跨 IPC 的对象用 `shallowRef`，并在发送前重新拼一个纯字面量。更根本的
  约束同上一条：IPC 参数必须是可结构化克隆的值，`ref` 深度代理不算。E2E 用合成
  `DragEvent` + `DataTransfer` 就能在无头环境里覆盖这条路径（见 `scripts/e2e-tab-reorder.mjs`）。
- **日期**：2026-10-22
- **状态**：有效（已落地）

### Windows 上中文看起来像衬线体

- **环境**：Windows 11，Electron
- **原因**：两处叠加。① 等宽字体栈以 `monospace` 泛型结尾，Windows 把其中的中文回退到
  **SimSun（宋体，衬线）**；`.mono` 被用在含中文的标签上（导航标题、页面副标题、表头）。
  ② 中文回退字体排在 Latin 字体之后且没有显式列出，某些环境会走 font linking 落到宋体。
- **解决**：等宽栈里显式列 CJK 无衬线字体（微软雅黑 / 苹方 / Noto Sans SC），并把泛型
  `monospace` 从栈里去掉；无衬线栈把 CJK 字体排在泛型之前。另外按「等宽只给技术数据」的
  原则，把含中文的标签从 `.mono` 移出。
- **验证方式**：用 canvas 逐字体绘制同一串中文并做像素哈希指纹，对比元素实际渲染结果。
  这是唯一可靠的判断方式——`getComputedStyle` 只返回栈，不告诉真实命中的字体。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 深色界面文字看不清

- **环境**：暗色主题，最小字号 8.5–9px
- **原因**：两层问题叠加。一是 `--faint` 对比度只有 2.71:1、`--dim` 3.46:1，远低于 4.5:1；
  二是大量辅助文字用了 8.5–9.5px，小字加低对比度几乎不可读。
- **解决**：重排 `tokens.css` 的灰阶层级，最低档提到 4.39:1 以上、主体档 8:1 以上；正文
  字号下限提高到 10px、主体 10.5–11.5px。浅色主题同步调整。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 任务栏图标发糊

- **环境**：Windows 11，任务栏 100% 与 150% 缩放，Electron 44
- **原因**：图标只有一张 256px PNG 塞进 ICO，或绘制时直接按目标尺寸画细线。Windows 会从
  单张大图缩放取 16/20/24/32px，细线在缩放后糊成一团；直接按小尺寸画则抗锯齿丢细节。
- **解决**：`scripts/make-icon.mjs` 用 4× 超采样绘制再按 alpha 加权降采样，并输出
  16/20/24/32/40/48/64/96/128/256 十档 ICO；小尺寸下把笔画加粗（4.2 单位），窗口图标另用
  1024px PNG。改图标后重新 `pnpm dist`，安装版才生效。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 浅色主题下标题栏的最小化/关闭按钮仍是深色

- **环境**：Windows 11，`titleBarStyle: "hidden"` + `titleBarOverlay`
- **原因**：`titleBarOverlay` 的颜色只在创建 `BrowserWindow` 时读取一次。切换主题只改
  `nativeTheme.themeSource` 和页面 CSS，不会重绘原生标题栏按钮，右上角会留一块深色。
- **解决**：主题变化时同时 `setBackgroundColor()` 与 `setTitleBarOverlay()`；并在 `loadFile`
  之后再补设一次（部分 Windows 版本上构造参数会被默认调色板覆盖）。深色/浅色各维护一组
  `{ color, symbolColor }`，高度与标题栏一致。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 主按钮在深色主题下 hover 变成灰底

- **环境**：任一弹窗的「保存」按钮，深色主题
- **原因**：`.btn:hover` 只写 `background: var(--surface-3)`，主按钮的渐变是
  `.btn.primary` 给的。两个类同时命中时 hover 规则优先级相等但更靠后，
  于是主按钮被刷成灰色，看起来像禁用。
- **解决**：主按钮必须显式重述 `.btn.primary:hover` 的背景渐变，再用
  `filter: brightness()` 做提亮。新增按钮样式时先检查是否有泛化的
  `.btn:hover` 会覆盖它。
- **日期**：2026-10-19
- **状态**：有效（已落地）

### 标题栏环境切换器看着「没垂直居中」

- **环境**：Windows，标题栏自定义下拉框
- **原因**：容器本身是居中的，但内部文本节点继承了 `line-height: 1.5`，
  旁边的徽标又是独立的字号，行盒高度不一致，视觉基线就歪了。

### 迁移把一个空数组当成「已是新格式」，站点清空、账号全部失联

- **环境**：Ensemble 1.0.0，Windows，工作区从 0.x 升级上来
- **症状**：站点页空了，但账号还在（挂在「未关联站点」分组下，或直接不显示）；
  编辑账号换站点保存也没用，下次打开还是原来的样子。
- **原因**：两个缺陷叠在一起。
  1. `sanitizeWorkspace` 的格式判定是 `Array.isArray(raw.sites) || !("environments" in raw)`。
     某个中间版本同时写了 `sites: []` 和仍有内容的 `environments`，于是这一份被当成
     「已经是 v2」，升级函数根本不跑 —— 站点列表读自空数组，账号的 `environmentId`
     也没被改名成 `siteId`。
  2. `saveIdentity` 的更新分支漏了 `siteId`：其他字段都写进去了，只有站点没写，
     所以表单报「已保存」而账号原地不动。

  两份列表，账号已有的 `siteId` 优先、否则回落到 `environmentId`；`saveIdentity`

  一个能被描述、能被修的状态，而不是一个静默的坏值。
- **教训**：**schema 判定不要用「新字段存在」当版本信号**。空数组、默认值、半迁移的

### 自建 DevTools 面板内容全空，reload 一次就永久坏掉

- **环境**：Electron 44.9.0，`setDevToolsWebContents` + 自建 `WebContentsView` 停靠面板
- **症状**：打开 DevTools 后每个面板（Elements / Console / Network）只有骨架，内容区一片空；
  而且「打开一瞬间正常、点一下语言切换就变空」。
- **原因**：**DevTools 前端只要 reload 一次，通信宿主就永久退化成 stub。**
  首次加载时前端拿到的 `InspectorFrontendHost` 是绑定在**被测页** frame 上的真实现，
  `sendMessageToBackend` 能用；reload 后 Electron 的
  `InspectableWebContents::ReadyToCommitNavigation` 在 `frontend_host_` 已存在时直接 return，
  新的 frame 拿到的是空实现的 stub，`JSON.stringify(host.sendMessageToBackend)` 可见
  `sendMessageToBackend(){}`。于是面板再也不会有数据。
  触发 reload 的正是「Switch DevTools to Chinese」——它要经宿主的 `loadNetworkResource`
  去取语言包，自建视图没有这个实现，取包失败回落到 en-US，白 reload 一次。
- **取证方法**（比截图可靠）：在 devtools target 里遍历 shadow DOM 找
  `ol.elements-tree-outline`，健康时 `childElementCount = 4~6` 且能搜到被测页的 `<html>/<head>`；
  坏掉后是 0。软渲染（`disableHardwareAcceleration`）下**永远正常**，所以先用它排除了
  「光栅化」这个曾经被误判的方向。
- **排除过的错解**：① 抖动视图宽度唤醒合成器（`reviveDevToolsCompositing`）——无效，
  和合成无关；② 换回 Electron 托管（不调 `setDevToolsWebContents`）——同样躲不过 reload，
  而且丢掉停靠能力；③ 关掉 DevTools 后新建视图重挂——无效，binding 在被测 WebContents 上。
- **解决**：绝不让前端 reload。提示条只点「Don't show again」（不触发导航）；面板里的
  F5 / Ctrl+R 不再直接放行，而是**转发给被测页**（重新加载页面，Chrome 也是这个语义），
  手势不废、前端不自毁。代价是 DevTools 界面保持英文——中文面板不值得一个空面板。
- **中文为什么不是「顺手的事」**：预置 `language=zh-CN` 到前端 localStorage 后首次加载，
  界面仍是英文（Elements 树的 `aria-label` 还是 `Page DOM`）；前端取语言包走
  `remoteBase` 指向 `chrome-devtools-frontend.appspot.com`，本机不可达；本地
  `devtools://devtools/bundled/locales/*.json` 也取不到（`Failed to fetch`），
  `loadNetworkResource` 直连同样超时。要中文得自带语言包并绕开 reload，是独立工作量。

### 自动填充填好了，但登录页一点反应也没有

- **环境**：内置表面 + SPA 登录页（按钮是 `type="button"`、提交逻辑写在脚本事件里）
- **症状**：账号密码都填进去了，页面停在原地，必须人再点一次「登录」。代码侧却一直回报
  `submitted: true`，日志上看不出任何异常。
- **原因**：提交动作只调了 `form.requestSubmit()`。`requestSubmit()` 在「表单没有 `submit`
  监听、按钮也不是 submit 类型」的页面上，发出的 `submit` 事件没有任何监听者，既不导航也
  不发请求，但它不会抛错——于是调用方把「事件发出去了」当成了「登录提交了」。
- **定位方式**：把实现临时回退成 `requestSubmit()` 跑 E2E，登录页把密码塞进了 URL 查询串
  （页面自己的读取逻辑跑了、登录处理器没跑），一眼就能看出是真点按钮和「只发事件」的差别；
  修复版同一断言下落到了落地页。**这类"看起来成功"的失败，只有让断言在被回退的实现上变红
  才能证明测试真的在测东西。**
- **解决**：`buildFillExpression` 改为先在 form（再退到 document）里找登录按钮并 `click()`，
  过滤掉 forgot / reset / show / register / cancel 之类干扰项，优先命中
  login / sign in / submit / 登录 等文字或表单内 `type=submit`；找不到按钮才退回
  `requestSubmit()`，最后 `form.submit()`。
- **附带改动**：自动提交从站点布尔上移为「全局默认 + 站点可选覆盖」，与默认浏览器同一套分层。

- **状态**：有效（已落地）

### 手动关掉浏览器窗口后，界面仍显示「运行中」

- **环境**：Windows + Edge/Chrome，CDP 模式
- **症状**：用户自己关掉浏览器窗口（或浏览器崩溃），Ensemble 的身份卡和运行面板仍显示运行中，
  点「停止」还在试图操作一个已经不存在的东西。
- **原因**：实例只存在于内存表里，启动后再没有任何地方观察浏览器的存活状态；只有应用自己调用
  `stopInstance` 才会移除条目。
- **排查陷阱**：第一版用 `child.on("exit")` 判断，结果每个实例启动后立刻被判退出。原因是 Edge/Chrome
  在 Windows 上会经兼容层重新拉起自己，我们 spawn 的启动器进程在窗口出现前就以 0 退出了，
  `child.pid` 根本不是浏览器进程。
- **解决**：
  - 存活信号改用 CDP socket：浏览器级 socket 关闭即视为退出，页面级 socket 作为兜底；
    进程退出信号只用于 Firefox（它不会自我移交）。

### 内置批量启动慢且中途切「无布局」直接断掉

- **环境**：Windows，Electron 44，内置表面批量启动
- **现象**：① 批量启动 N 个账号要等 N 个页面**串行**加载完，每个都数秒；② 批量中途把视图布局
  切成「无布局」，批量当场中断，已开的页留在原地、后面的不再开。
- **原因**：批量是渲染层的一个 for 循环逐个 `await openEmbeddedTab`，主进程每次 `createTab`
  都要 `await loadURL` 等完整加载，总时长 = 各页相加。中断则是竞态：循环开头记下的 `slotCount`
  是布局切换前的快照，切到无布局后循环仍按旧值调 `pinEmbeddedTab`，主进程 `pinTab` 对越界
  槽位直接抛「槽位不存在」，循环没有 try/catch，整批死掉。
- **解决**：整个批量下沉到主进程一个 IPC（`IPC.embeddedLaunchBatch`）：页内并发建页（并发度 3，
  总时长 ≈ 单页时长 × ⌈N/3⌉）、落格时**实时重读槽数**、越界槽位静默跳过（溢出页留在视图离台
  停放，与手动拖放的规则一致）、任一失败整批连同容器一起回收（原子性对齐外置路径）。注意
  「无布局」的槽位语义是 **1 个整舞台格**（`embeddedSlotRects` 对空槽预设回退满屏矩形），不是
  0 格——第一页上台、其余停放。渲染层不再编排多步 IPC。守护：`e2e-batch-launch.mjs` 的
  Free 布局场景。
- **教训**：多步 UI 操作不要让渲染层编排——「用户中途改设置」会击穿任何调用前算好的假设；
  把整批动作收进一个原子入口，竞态和原子性一起消失。
- **日期**：2026-10-30
- **状态**：有效（已落地）

### 窗口关掉后进程不退，portable exe 一直被占用

- **环境**：Windows，Electron 44，安装版与便携版均复现
- **症状**：关闭窗口后 `Ensemble.exe` 仍在任务管理器里，没有可见窗口；因为是 portable 启动的，`release\Ensemble-0.1.0-win-x64-portable.exe` 被锁住无法覆盖。用户会以为「已经关了」，但实际上一堆进程还在后台。

### 内置浏览器：F12 打开 DevTools 后立刻被同一次按键关掉

### 内置浏览器：DevTools 前端 reload 后面板全空，但换掉前端视图就能救回来

- **环境**：Electron 44.9.0，`setDevToolsWebContents` 自托管前端（Electron 托管的前端同样中招）
- **现象**：DevTools 里改设置后它要求 reload，一 reload，Elements / Console / Network 全部
  只剩骨架，内容永远空。
- **实测判据**（截图不可靠，用这两条）：① 递归 shadow DOM 找 `ol.elements-tree-outline`，
  健康时 `childElementCount > 0` 且能找到被测页 DOM，坏掉立刻为 0；②
  `InspectorFrontendHost.sendMessageToBackend` 的源码——健康时转发到 `DevToolsAPI`，坏掉是

- **原因**：首次加载时前端拿到绑定在被测页上的 host；reload 后 Electron 给它一个 stub。

  还没销毁，新前端绑到空处），必须等——这是旧结论「重建也没用」的来源。

  这是设置页「恢复默认」走的路径）与第二次 `did-finish-load`（兜底不经过可拦导航的 reload）。
  用户在等待期间关面板会取消重建。
