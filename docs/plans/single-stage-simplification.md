# 单舞台简化计划

> **状态（2026-11-17）**：方案已拍板，未开工。分 P0 / P1 / P2 三期推进，验收标准见 §五。
> 应用内分屏与应用内多视图的取舍及被否方案见
> ADR [0012](../architecture/adr/0012-no-in-app-split-screen.md)。

> 这份是给人看的：要改什么、为什么改、按什么顺序、哪些不做。

## 一、背景

真实用户反馈：太复杂，不如 v1 好用。具体困惑集中在四处：

1. **两条标签条分不清。** 顶部的标签条是页面，左侧的标签条是浏览器实例，两处都叫
   「标签页」，形态相近。
2. **新建空白会话不空白。** 新建时默认带上了站点预选，并停在账号选择的 tab 上，
   「就想开个空白页看看」要先把多余的东西清理掉。
3. **视图看不懂。** 视图是运行栏上的分组，但它同时是启动分组、布局排列和停靠分组，
   用户无法从名字推断它管什么。
4. **账号与档案分不清。** 两个词、两个页面，边界是什么要试过才知道。

根因有两条：

- **视图一个对象背了三个职责**：启动分组、布局排列、停靠分组。三个职责各自变化，
  用户看到的却是同一个名字。
- **主导航平铺了 12 个页面组件**：站点、账号、视图、档案、流程、书签、标签、消息、
  AI 记录、设置、浏览器、新标签页。入口层概念过载，每个词都要用户建一次心智模型。

## 二、目标心智模型

改造完成后，用户面对的模型是：

- **舞台永远一格。** 当前选中的浏览器实例上台，其余实例在后台运行——登录态保持、
  AI 可继续驱动，只是不占像素。
- **顶部双行。** 第一行是实例行：头像色块 + 账号名 + AI 状态点，行尾是 [+启动]，
  右上是 [管理] 按钮；第二行是当前实例的页面标签行。实例行横向溢出时横向滚动，
  溢出部分折叠为「+N」。
- **无侧边栏。**
- **AI 状态是三态点。** 正在操作 = 呼吸点；30 分钟内动过 = 常亮点；其它 = 无标。
  hover 显示最后动作时间；明细在 AI 记录页查看。
- **管理收敛为独立窗格/窗口**，内含四页：站点、账号、AI 记录（流程并入为一个 tab）、
  设置。书签、标签、消息、档案四个页面从导航消失（档案并入账号，见 §三 P1-4）。

## 三、要做的事

### P0：行为修正（不动概念）

在概念收敛之前先修正三处可直接观察到的行为。界面结构与概念词汇保持原样。

1. **实例行显示账号名。** 实例行与页面标签行各自显示正确对象的名字：
   实例行条目 = 账号名，标签行条目 = 页面标题。账号名与身份列表一致，
   不随被测页面标题变化。
2. **新建空白会话真空白。** 点击后舞台加载空白页，地址栏无预填站点，
   不弹出账号选择面板。
3. **AI 活动指示改三态点。** 实例条目上的操作次数数字改为三态点
   （呼吸点 / 常亮点 / 无标），hover 显示最后动作时间。

### P1：概念收敛

1. **顶部双行改造 + 无侧边栏。** 左侧标签条并入顶部成为实例行，主界面只留
   实例行与页面标签行两条横向结构。
2. **管理窗格。** 站点、账号、AI 记录、设置四页收进独立窗格/窗口，
   主界面右上 [管理] 进入；主界面常驻入口只有 [+启动] 与 [管理]。
3. **视图退役。** workspace 数据里的 `views` 字段静默保留（读写 round-trip
   不丢字段），UI 上无视图页与创建入口。「启动一组账号」退化为多选批量动作：
   选中多个账号 → 全部启动 → 第一个上台、其余挂后台。保存组合不是一级概念；
   未来如有真实需求，在设置里另立「启动预设」，当前不做。
4. **档案并入账号。** 默认所有账号共用一套默认档案；「独立隔离档案」成为账号
   创建表单里的高级折叠项（默认收起）；档案页撤除。检测到多档案存量时，
   设置页出现一次性迁移向导，把既有档案逐个并到对应账号上。
5. **流程并入 AI 记录。** 流程页成为 AI 记录页里的一个 tab，入口合一。
6. **导航收敛。** 主界面常驻导航项收敛为 [+启动] 与 [管理] 两个；
   书签、标签、消息、档案页面从导航消失。

### P2：拆窗

1. **技术 spike。** 把一个实例的页面容器（`WebContentsView`）挂到独立
   `BrowserWindow`，先验证三件事：跨窗口迁移时的焦点归属、关闭独立窗后的实例回收、
   最小化状态下截图仍可获取。结论落在 ADR 附录或踩坑库，作为实现依据。
2. **拆窗实现。** 实例可拆出到独立 OS 窗口，配合系统分屏与多显示器；
   多账号并排对比由此承接，应用内不提供分屏（ADR 0012）。
3. **槽位机制收缩。** UI 单格化后内部先保留 1 槽，随后逐步拆除
   `embedded-cell-geometry` / `embedded-slots` 的几何与多槽代码及对应测试。

## 四、顺序与依赖

```
P0 行为修正（三个修正互相独立，可并行）
     ↓
P1 概念收敛（1 → 2 → (3 / 4 / 5 可并行) → 6 收口）
     ↓
P2 拆窗（spike 先行 → 实现 → 槽位收缩）
```

- **P0 排在最前**：它不动概念，改完即可缓解四条用户困惑里的两条（①②），
  为 P1 争取观察窗口。
- **P1 内部**：双行改造（1）是管理窗格（2）的前提——侧边栏腾出来之后，
  [管理] 才有唯一入口可言；视图退役（3）、档案并入（4）、流程并入（5）
  互相独立，可并行；导航收敛（6）最后做，它是前五项的汇总断言。
- **P2 排最后**：拆窗依赖单舞台心智模型已落地；槽位收缩依赖 UI 已单格化。

## 六、这次改造不动的东西

- **身份隔离**：每个身份一个独立 profile 目录、独立 `persist:` 分区，
  `sandbox` / `contextIsolation` / `nodeIntegration` 三件套
- **凭据安全**：凭据不进渲染进程，填充在主进程完成，MCP 永不返回明文密码
- **不打包浏览器**：引擎来自系统安装
- **MCP 权限档位**：read / write / run / danger 分档与审计日志脱敏照旧
- **退出顺序**：先停 MCP → 销毁托盘 → 回收浏览器
- **`core` 层边界**：不依赖 Electron，可在纯 Node 下测试

以上均为仓库 AGENTS.md 的硬约束，本计划不触碰。
