# 路线图

记录方向判断，不代表已排期。每条做完后从「计划」移出并落到对应文档。

## 定位

Ensemble 是**多身份权限验证工具**，不是抗检测工具。所有功能都应服务于「同一套系统里，不同角色看到的和能做的是否正确」，而不是「如何让平台认不出是同一个人」。

因此不做指纹伪造（canvas / WebGL / 字体列表等）：那需要自行维护改过的浏览器内核，与「驱动系统真实浏览器、行为与真人一致」的前提冲突，也与本项目的用户协议定位相悖。

## 近期（成本低，直接改善首用体验）

### 会话健康中心

一键检测全部身份的登录态，聚合成一个列表：已过期、未检查、正常。支持批量重新登录。
`checkAuth` 已存在，缺的是聚合逻辑与界面。

判据：一个环境有 8 个身份时，能在一屏内看清谁掉线，并一次拉起需要重登的窗口。

### 恢复上次场景

登录态本来就留在 profile 里，应用启动时把上次使用的场景重新拉起即可。成本很低，但对「每天固定测同一套权限」的用户差别很大。

判据：冷启动后不需要重新点场景、重新排窗口。

### 首次引导

新用户第一次打开是一张白纸。做三步向导：建环境 → 加身份 → 配场景，每步都能跳过。
对开源项目的留存影响通常大于任何单个功能。

## 中期（真正的差异化）

### 身份对比

同一个 URL 用两个身份打开，对比截图与 DOM，直接回答「删除按钮是不是只有管理员能看到」。
这是权限测试的核心动作，目前没有顺手的产品做。

实现要点：

- 两侧都通过 CDP 取同一路径，统一视口尺寸后再截图，避免分辨率差异造成假阳性
- DOM 对比只比可见元素的文本与可访问名称，不比 class 名（构建工具会改）
- 输出「A 有 B 无」「B 有 A 无」两栏，附带元素定位信息

### 权限断言

给场景配置一组断言：某元素对某身份应可见 / 不可见。一键跑完出报告，可导出为 QA 证据。

断言的表达要尽量窄，先支持两种：

- 选择器存在 / 不存在
- 选择器可见 / 不可见

不做「点击后应发生什么」这类流程断言，那会把工具推向通用 E2E 框架，与 Playwright 正面竞争且不占优势。

### MCP 暴露对比与断言

新增 `compare_identities`、`assert_element_visible` 等工具，让 AI 能自己跑权限回归，而不只是录入数据。
这是本产品与通用浏览器自动化的分水岭：AI 知道「谁应该看到什么」，工具负责验证。

## 远期（可选，取决于真实需求）

### 身份级代理

若确有跨地域访问被测系统的需求（验证地域策略、代运营场景），加 `--proxy-server` 启动参数即可。
定位是**网络路径测试**，不做成反检测能力，文档中也不使用这类措辞。

### 批量导入身份

CSV 导入：名称、账号、角色、备注。没有 AI 客户端的用户也需要批量建号。

### 浏览器扩展形态的快速切换

同一网站的多个账号，Chrome 自带 Profile 已解决隔离，痛点在切换。
若要做，更适合做成轻量切换器；本项目的价值应落在「切换之后验证行为差异」，即身份对比与权限断言。

## 明确不做

| 方向 | 原因 |
| --- | --- |
| 指纹伪造与反检测 | 需自维护浏览器内核，与「真实浏览器」定位冲突，且用户群与开源定位不符 |
| 内置浏览器内核 | 放弃厂商更新与真实行为，安装包体积翻数倍 |
| 通用 E2E 测试框架 | 与 Playwright / Cypress 正面竞争，没有差异化 |
| 云端账号存储 | 纯本地是安全边界的一部分，密码不出本机 |
