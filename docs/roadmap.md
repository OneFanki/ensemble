# 路线图

记录方向判断，不代表已排期。每条做完后从「计划」移出并落到对应文档。

## 定位

Ensemble 是**多身份并行工作台**，不是抗检测工具。核心命题是「同一套系统里，多个身份同时在场，
并行操作、并排对比，验证每个身份看到的内容和能做的操作是否符合预期」。

「权限验证」只是最容易理解的例子，不是能力边界。典型场景还包括：

- 角色与权限：管理员看到删除按钮，普通成员看不到
- 多租户与数据隔离：租户 A 不该看到租户 B 的数据
- 功能开关与灰度：同一功能对不同账号是否按预期放开
- 套餐与等级差异：免费版和付费版的功能边界
- 跨账号协作：A 提交、B 审批，两边状态是否同步正确

所有功能都应服务于「同一套系统里，不同身份看到的和能做的是否正确」，而不是「如何让平台认不出是同一个人」。

因此不做指纹伪造（canvas / WebGL / 字体列表等）：那需要自行维护改过的浏览器内核，与「真实浏览器行为」的前提冲突，也与本项目的用户协议定位相悖。

## 两种浏览器表面

浏览器分内置与外部两种表面（决策见
[ADR 0006](./architecture/adr/0006-embedded-browser-first.md)）：

| | 内置（`WebContentsView`） | 外部（系统浏览器） |
| --- | --- | --- |
| 可控性：截图、接管、录制、并排、布局 | 完整 | 受限 |
| 保真度：真实版本、扩展、DRM、企业策略 | 较弱 | 最强 |

- **内置是默认与主推**：AI 驱动、静默运行、日常操作、并排对比都在这里，全程不弹系统窗口，
  人随时可以看和接管。
- **外部是保真校验**：需要确认「在用户真实环境里也一样」时切换。外部只承诺保真，
  不承诺与内置相同的功能集。
- 两者共用同一套站点、账号、凭据、视图与布局模型；切换必须由用户显式触发，因为它意味着重新登录。

## 已完成

### 浏览器表面：视图与标签页（0.5 地基）

`WebContentsView` 承载页面，画在主窗口的「浏览器」页里——不再有独立的内置浏览器窗口。
带搜索的导航顺序是 浏览器 / 站点 / 账号 / 视图 / 设置，浏览器是默认页。

- **视图是一块共享屏幕区域**：容器记住自己的布局、格位与聚焦标签，同一时刻只有一个
  在台上，其余视图的页面继续在窗口外运行（不是隐藏，见设计文档）。
- 内置表面布局五档（free / 2x1 / 1x2 / 2x2 / 3x1；`1x1` 与「无布局」是同一件事，已合并）
  + 自定义预设；容器的布局改动写回视图定义，下次启动保持一致。格位之间可以拖分隔缝改比例。
- 右侧运行栏跨所有页面常驻，把内置视图、内置扁平标签与外置实例放在同一处；视图是块、
  标签是行，可折叠、可整栏收起成带角标的窄边。
- 视图只手动创建：运行栏标题栏的「创建视图」按钮给一块空视图（默认 2×1、默认名可双击或
  右键改），空视图不会自动回收；拖标签只在列表内排序、或拖进已有视图，不会顺手建组。
- 每个身份独立 `persist:` 分区。MCP 暴露 14 个浏览器工具，新增 `open_browser_view`；
  布局与格位工具默认作用于台上的视图，全是扁平标签时会先分组。

控制通道走进程内 `webContents.debugger`，不开放任何调试端口；鉴权沿用已有的 MCP token。
页面读取只返回可见元素，因此「这个账号能看到什么」就是快照本身。

首个用途是让 AI 在一个窗口里驱动多个账号跑真实流程，人在旁边看，随时可以接手。

### 账号引用与地址变更检测

- 账号可以引用另一个站点的账号（`passwordMode: "reference"`）：用户名、密码、显示名、
  角色、颜色、备注完全同步，登录态与 profile 各自独立；改来源就同步到所有引用方。
- 引用只允许一层；断开引用时把解析出的密码落成本地 `custom`，不会回退到站点默认密码。
- 删除来源账号时，把密码物化到所有引用方后自动断开，避免留下无法启动的悬空身份。
- 站点记住最近一次成功填充的 origin；地址变了会拦住填充并请求一次显式确认。

### 视图跨站点复制

把一套编排搬到另一个站点：目标站点已有的同名账号直接复用，没有的建引用账号；
副本记录 `copiedFrom`，来源成员匹配不到的会在结果里列出。

### 首次引导

三步向导（建站点 → 加账号 → 配视图），每步可跳过，可在设置里重播。

### 运行实例悬浮条

桌面置顶小条列出所有运行中的身份，按站点分组，点击即把对应浏览器窗口提到最前
（最小化会恢复，不重启不重载）。取代了「浏览器扩展形态的快速切换」设想：扩展要单独打包、
上架、处理扩展与本地的授权，成本高，而痛点只是切窗口。

### 会话健康中心

身份页入口，一屏按「正常 / 已过期 / 未确认」分类；支持一键检测全部、
一键为所有过期身份打开登录页并填入凭据。检测只按需触发，不做后台轮询；
没开窗口的身份用不显示窗口的后台浏览器读取该 Profile 的 Cookie 完成检测，
查完立即关闭，不会多出窗口。

### 恢复上次视图

设置项（默认关闭）。开启后冷启动等引擎扫描完成，再在内置浏览器里按原布局恢复上次
使用的视图；视图已删除则静默清理记录。

## 中期（真正的差异化）

### 身份对比

同一个 URL 用两个身份的内置标签页打开，对比可见元素与截图，直接回答
「删除按钮是不是只有管理员能看到」。

内置表面让这件事几乎白送：同一窗口、同一视口、各自截图，不用再处理窗口位置、
边框遮挡与 DPI 差异。

实现要点：

- 两侧统一视口尺寸后再截图，避免分辨率差异造成假阳性
- DOM 对比只比可见元素的角色、可访问名称与稳定选择器，不比 class 名
- 输出「A 有 B 无」「B 有 A 无」两栏，附带元素定位信息

### 权限断言

给视图配置一组断言：某元素对某身份应可见 / 不可见。一键跑完出报告，可导出为 QA 证据。

断言的表达要尽量窄，先支持两种：

- 选择器存在 / 不存在
- 选择器可见 / 不可见

底层的可见性判定已经在 `check_element_visible` 里实现，断言层只是把它按视图批量跑一遍。

不做「点击后应发生什么」这类流程断言，那会把工具推向通用 E2E 框架，与 Playwright 正面竞争且不占优势。

### 操作录制

内置表面天然适合录制：每个 view 拿到的都是干净的单标签画面，没有窗口边框、
不受其他窗口遮挡、视口精确。定位是「把 AI 跑过的一轮流程录下来给人看」，
不是屏幕录像工具。

### 会话预热与运行模式

AI 触发时默认在后台运行，需要人看时再把窗口提到前台。配合已有的会话健康检测，
让「打开就能接着用」成为默认体验。

## 远期（可选，取决于真实需求）

### 身份级代理

若确有跨地域访问被测系统的需求（验证地域策略、代运营场景），加 `--proxy-server` 启动参数即可。
定位是**网络路径测试**，不做成反检测能力，文档中也不使用这类措辞。

### 批量导入身份

CSV 导入：名称、账号、角色、备注。没有 AI 客户端的用户也需要批量建号。

### 自建 Chromium 分支

只有在内置表面受限于 Electron 的升级节奏、且这件事真的成为瓶颈时才考虑。
代价是长期维护 Chromium 升级、安全补丁、编解码与签名分发。

## 明确不做

| 方向 | 原因 |
| --- | --- |
| 指纹伪造与反检测 | 需自行维护改过的浏览器内核，与「真实浏览器行为」定位冲突，且用户群与开源定位不符 |
| 把内置分区当作指纹隔离手段 | 分区只隔离 Cookie 与存储，不做 canvas / WebGL / 字体伪装 |
| 通用 E2E 测试框架 | 与 Playwright / Cypress 正面竞争，没有差异化 |
| 浏览器扩展形态的切换器 | 需单独打包、上架并处理扩展授权，成本高于收益；切换痛点已由运行实例悬浮条解决 |
| 云端账号存储 | 纯本地是安全边界的一部分，密码不出本机 |
| Chrome 平替（书签、扩展商店、密码管理器、同步） | 内置浏览器的定位是 AI 优先的工作台，不跟通用浏览器比功能广度 |
